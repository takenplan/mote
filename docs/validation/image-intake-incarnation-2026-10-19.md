# Current image intake while retired physical work settles

The production regression is a new allowed source incarnation accepted while
the previous incarnation's real OCR HTTP request remains held. The old request
must retain physical occupancy, while the current original must retain its own
durable intake. Disabled processing preserves a genuine zero-attempt blocked
coordinator, as specified in [Files behavior](../design/multiuser-files.md).

The controlled RED uses the real 24a public ingress, source deletion/recreation,
Perception configuration, proof retry, M05 and generated loopback OCR listener.
An external observer records `submitSync` before/after admission and its thrown
error without changing the candidate source. It confirmed
`external_result_unknown`/409 before the `mp_admissions` insert, a rejected
`submitIntake`, an accepted receipt, and one still-held HTTP call. This is a
production admission omission, independently of the empty image jobs DTO.

The minimal repair changes only automatic intake's final coordinator admission.
The existing pipeline remains responsible for waiting on retired live I/O and
blocking unknown results before any physical child is admitted.

The first five rows are durable real-entry regressions in
`apps/server/test/multiuser-processing-intake-incarnation.test.ts`. They use
generated bytes and loopback fixture providers, without live models or personal
screenshots. Broader affected checks and the combined Life journeys belong to
the integration driver for the new frozen head.

The Web fixture barrier binds the proof of the current incarnation and waits
for the actual M05 blocked state within its existing bound. Receipt acceptance
alone is not a guarantee that the first read is already blocked. The Files
branch contains the original four progress tests; the combined candidate's
additional source-incarnation case must call this barrier before its blocked
assertion. The integration hunk preserves its later privacy assertions.

## Responsibility audit

- **KEEP:** current original/head, owner epoch, policy, Perception, attachment and
  cancellation authorization; per-incarnation intake deduplication; public/manual
  unknown confirmation; physical unit occupancy; generation and late-publication
  fences; source recreation and capture-delete tombstone semantics.
- **CHANGE:** automatic intake records an authorized current coordinator before
  old physical work settles, using the same deferred physical admission boundary
  already used by policy reconciliation.
- **REMOVE:** the pre-insert physical rejection from this intake path. The
  physical guard and confirmation checks remain at their existing execution and
  public/manual boundaries.
- **EXCEPTION:** explicit public/manual processing retains its synchronous
  physical rejection; archive-only, cancelled, forgotten or unauthorized intake
  gains no new admission authority.
- **UNKNOWN:** whether the combined Life stale-read, restart and capture-delete
  journeys all pass on the next integration candidate; unrelated Ask and hot
  failures have no established causal relationship to this repair.

No settings defaults, deadlines, user steps, retention policy, intent
classification, wire/storage versions or translations change.
