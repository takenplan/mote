# 飞书文档上下文验证（2026-10-15）

本轮实现见 [ADR](../adr-feishu-document-context.md)、[接入说明](../lark-integration.md) 与 [场景及状态矩阵](../testing-feishu-document-context.md)。素材、人物、账号和提供方响应均为生成 fixture；没有读取真实飞书文档、个人屏幕或物理设备。

## 实际链路

生成官方 CLI 响应 → 正常 owner HTTP 连接、保存范围、预览、首次确认与同步 → SQLite 原件和不可变修订 → 正式 Material → 实际后台自动 Memory 提取及独立审核 → owner HTTP 问答及原文引用。只有上游 CLI 传输边界被替换；Memory 与问答使用实际 `gpt-6.1-sol / high`。未手工调用内部 Memory 队列代替用户入口。

预览阶段没有正文调用、原件发布或模型工作。第一次归档保存 9 篇正文和 9 条活动观察；方案改版后保存第二版正文及新的编辑条件匹配观察。当前归档为 9 篇文档、10 条独立活动线索，项目正文有两个历史版本。正文与活动具有独立身份，不把搜索结果当作逐次行为日志。

实际持久化 **10 条卡片：5 条精选 Memory、4 条有效观察、1 条过时观察**。精选分别来自日记、收藏用途、学习经验、个人复盘和生活计划。有效观察包含周报进度、修订后的方案及两条编辑筛选观察。旧会议与初稿曾合并为一张观察，方案改版后整张卡标为 `stale`；会议原文仍可检索。第三方手册没有生成派生卡，但原文和打开条件匹配观察仍归档。

所有卡片均有实际独立审核记录；脚本逐条核对引用、偏移和原文，未用预期结果替代持久化内容。

| 场景 | 实际 Memory | 用户实际得到的反馈 |
| --- | --- | --- |

| 方案修订 | 旧观察过时，新修订与编辑条件观察有效。 | 实际调用历史读取，对比第一版与第二版：全量改增量、变更理由，以及实施和生产验收未完成。 |
| 工作周报 | 进度观察与编辑条件范围观察。 | 区分原型完成、灰度未开始、访谈未预约和权限未确认，没有推断逾期或失败。 |

| 个人复盘 | 精选同类接入先验证只读授权、响应格式的意向。 | 解释延期一天及权限阻碍，限定同类接入，没有声称新顺序已执行。 |
| 生活计划 | 精选十一月京都意向及本次安排偏好。 | 少换住处、行程留白、交通比较中；当时未订票住宿，未找到后续成行证据。 |
| 第三方手册 | 无派生精选，正文和打开条件观察可检索。 | 引用作者建议与平台观察，限定测试环境、升级顺序及备份建议；不能证明本人阅读、读完、认可、执行或验收。 |

每个实际回答包含 1–2 条原文引用。收藏案例使用本人维护的收藏备忘，没有伪造提供方未返回的“收藏”动作，也没有读取其引用链接的全文。

## 发现与修正

初轮自动语义评审为 7/9，Memory 本身为 9/9。独立复核发现两个原因：评审分组错误地把同一项目的关联资料视为不可使用；手册回答把局部“建议备份”写成“要求备份”。前者是评估上下文缺陷，后者是轻微但真实的措辞精度问题。

评审现提供全套已与归档逐字核对的生成原文，分组只限制评分对象，不限制跨文档检索。普通归档问答增加通用规则，保留原文说话人、范围和建议／要求／意向的强度；没有加入场景关键词、固定工具顺序或 Memory 特例。只重跑手册的实际 HTTP 问题，回答已恢复“建议升级前备份”，继续保留提供方打开信号的限制。其他八个回答和已完成的提取、审核均复用，不能把这写成九例全部在新提示词下重新生成。

修正后对实际持久化卡片和九个实际回答重新进行独立模型评审，**9/9 的 Memory 与回答均通过**，最终报告为 `status=passed`、`semanticQualityAccepted=true`。这是同一生成库上的定向修正及复核，不是对未见过的真实资料的质量保证。

验收驱动还修正了 Material 分页上限、修订后旧批次的正常失效、等待当前修订进入自动工作，以及评审问题的 20,000 字符入口限制。最后一项采用三组有完整证据的评审，没有截断正文或卡片。初始诊断报告及失败评审保留，不覆盖为成功记录。

报告存放在 Git 外的系统临时目录 `mote-lark-documents-live-DHRlTw`。恢复过程复用同一生成库，逐字核对原件，并记录原提取模块哈希和恢复时的完整 server/shared/agent 源码哈希。日历授权选项的差异和后续问答提示词的唯一差异均单独核验、记录；没有把恢复后的代码冒称为原提取代码。仓库中的正式脚本要求恢复时完整源码哈希匹配，本轮过渡恢复适配仅保存在忽略目录，未降低正式恢复门禁。

本库实际记录 29 次外层 Agent 调用：28 次完成，1 次在入口因评审问题超长而被本地拒绝。成功调用包括 12 次提取／审核、10 次用户问题（手册一次定向复验）和 6 次独立评审。另一个早期诊断库有 8 次已完成的提取／审核，没有计入本库结果。外层调用不等于供应商 HTTP 请求次数；账本的金额为空，没有据此估价。

## 验证边界

本轮没有真实飞书租户授权、搜索覆盖、跨组织可见性、索引延迟或 API 自读污染的实测，也没有物理设备采集或系统授权交互。提供方打开条件可能包含连接器访问；不能证明人类阅读、阅读时长、认同或确切所见版本。宽泛历史范围不能完整恢复某日逐次行为。图片、附件、嵌入 Sheet/Base 仍只保存引用。

九例是生成的定向语料，不代表未见过的真实资料保留集或长期运行质量。后台整合和洞察不是本次提取与问答验收对象。模型账本记录实际用量，但供应商请求次数与金额不可用时保持未知，不以外层 Agent 调用数估算费用。
