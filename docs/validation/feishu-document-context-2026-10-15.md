# 飞书文档上下文验证（2026-10-15）

本轮实现见 [ADR](../adr-feishu-document-context.md)、[接入说明](../lark-integration.md) 与 [场景及状态矩阵](../testing-feishu-document-context.md)。前半部分记录最初九场景验收：素材、人物、账号和提供方响应均为生成 fixture，没有读取真实飞书文档、个人屏幕或物理设备。文末另记同日真实租户中四篇新建合成文档的补验，两轮结果分别保留。

## 实际链路

生成官方 CLI 响应 → 正常 owner HTTP 连接、保存范围、预览、首次确认与同步 → SQLite 原件和不可变修订 → 正式 Material → 实际后台自动 Memory 提取及独立审核 → owner HTTP 问答及原文引用。只有上游 CLI 传输边界被替换；Memory 与问答使用实际 `gpt-6.1-sol / high`。未手工调用内部 Memory 队列代替用户入口。

预览阶段没有正文调用、原件发布或模型工作。第一次归档保存 9 篇正文和 9 条活动观察；方案改版后保存第二版正文及新的编辑条件匹配观察。当前归档为 9 篇文档、10 条独立活动线索，项目正文有两个历史版本。正文与活动具有独立身份，不把搜索结果当作逐次行为日志。

实际持久化 **10 条卡片：5 条精选 Memory、4 条有效观察、1 条过时观察**。精选分别来自日记、收藏用途、学习经验、个人复盘和生活计划。有效观察包含周报进度、修订后的方案及两条编辑筛选观察。旧会议与初稿曾合并为一张观察，方案改版后整张卡标为 `stale`；会议原文仍可检索。第三方手册没有生成派生卡，但原文和打开条件匹配观察仍归档。

所有卡片均有实际独立审核记录；脚本逐条核对引用、偏移和原文，未用预期结果替代持久化内容。

## 发现与修正

初轮自动语义评审为 7/9，Memory 本身为 9/9。独立复核发现两个原因：评审分组错误地把同一项目的关联资料视为不可使用；手册回答把局部“建议备份”写成“要求备份”。前者是评估上下文缺陷，后者是轻微但真实的措辞精度问题。

评审现提供全套已与归档逐字核对的生成原文，分组只限制评分对象，不限制跨文档检索。普通归档问答增加通用规则，保留原文说话人、范围和建议／要求／意向的强度；没有加入场景关键词、固定工具顺序或 Memory 特例。只重跑手册的实际 HTTP 问题，回答已恢复“建议升级前备份”，继续保留提供方打开信号的限制。其他八个回答和已完成的提取、审核均复用，不能把这写成九例全部在新提示词下重新生成。

修正后对实际持久化卡片和九个实际回答重新进行独立模型评审，**9/9 的 Memory 与回答均通过**，最终报告为 `status=passed`、`semanticQualityAccepted=true`。这是同一生成库上的定向修正及复核，不是对未见过的真实资料的质量保证。

验收驱动还修正了 Material 分页上限、修订后旧批次的正常失效、等待当前修订进入自动工作，以及评审问题的 20,000 字符入口限制。最后一项采用三组有完整证据的评审，没有截断正文或卡片。初始诊断报告及失败评审保留，不覆盖为成功记录。

报告存放在 Git 外的系统临时目录 `mote-lark-documents-live-DHRlTw`。恢复过程复用同一生成库，逐字核对原件，并记录原提取模块哈希和恢复时的完整 server/shared/agent 源码哈希。日历授权选项的差异和后续问答提示词的唯一差异均单独核验、记录；没有把恢复后的代码冒称为原提取代码。仓库中的正式脚本要求恢复时完整源码哈希匹配，本轮过渡恢复适配仅保存在忽略目录，未降低正式恢复门禁。

本库实际记录 29 次外层 Agent 调用：28 次完成，1 次在入口因评审问题超长而被本地拒绝。成功调用包括 12 次提取／审核、10 次用户问题（手册一次定向复验）和 6 次独立评审。另一个早期诊断库有 8 次已完成的提取／审核，没有计入本库结果。外层调用不等于供应商 HTTP 请求次数；账本的金额为空，没有据此估价。

## 生成响应验收的边界

上述九场景运行没有真实飞书租户授权、搜索覆盖、跨组织可见性、索引延迟或 API 自读污染的实测，也没有物理设备采集或系统授权交互。提供方打开条件可能包含连接器访问；不能证明人类阅读、阅读时长、认同或确切所见版本。宽泛历史范围不能完整恢复某日逐次行为。图片、附件、嵌入 Sheet/Base 仍只保存引用。

九例是生成的定向语料，不代表未见过的真实资料保留集或长期运行质量。后台整合和洞察不是本次提取与问答验收对象。模型账本记录实际用量，但供应商请求次数与金额不可用时保持未知，不以外层 Agent 调用数估算费用。

## 真实租户补验（同日）

在真实飞书账号中新建一个隔离文件夹和四篇合成文档：日记、会议纪要、收藏备忘、方案草案。通过官方 CLI 1.0.97 创建，并逐篇回读核对；随后使用 Mote 固定的官方 CLI 1.0.85 执行实际目录发现和正文读取，没有替换提供方响应。文档中的林澄、周遥、许岚和松影项目均为虚构测试对象，来源上下文也明确它们不是真实账号持有者的经历。没有读取已有私人文档或个人截图。

### 授权和执行范围

既有本地 CLI 登录通过原生 `auth status --json --verify`：用户身份 `ready`、token `valid`、`verified=true`，所需文档及知识库读取权限齐备，文件夹已有新版只读 `space:document:retrieve`；没有旧版 `drive:drive:readonly` 或完整 `drive:drive`。

本次最终复用已有登录，没有再次申请权限。测试专用 Mote 库从真实 CLI 身份恢复已连接配置，再通过正常 owner HTTP 检查、范围保存、预览和确认同步。此恢复是测试前置条件，不是产品新增的全局 CLI 接入入口，也不等于首次设备码 OAuth 验证。此前新配置的扫码尝试没有完成，未计为通过。

同步范围只选择新建测试文件夹，手动固定文档为空，创建／编辑／打开自动发现关闭，自动定时同步关闭。确定性隐私边界检查每个目录成员、标题、正文及后续修订都与固定合成语料一致；非白名单结果在进入模型前失败。Mote 库和原始报告留在仓库外的权限受限临时目录，现有生产 Memory 未写入这些测试经历。

### 实际链路和持久化结果

实际预览发现 **4/4 篇文档**，产品正文调用、原件发布和模型调用均为零。确认后保存四篇正文，经正式 Material 和正常后台自动提取、独立审核，首轮发布 **2 条精选 Memory、1 条观察**；没有手工触发内部 Memory 队列。

随后在真实飞书中局部修改方案段落，并回读确认：全量索引草案改为增量索引决定，原因是合成测试中首次全量耗时过长，实施和生产验收仍未完成。再次通过目录预览和正常同步保存第二版；当前仍为四篇正文，方案有两个不可变历史版本，归档没有伪造任何活动事件。

### 语义评审和复核

首次独立评审的 Memory 为 **4/4**，回答为 **3/4**。唯一否决针对收藏回答末尾“未检索到后续改变这一状态的相关记录”：评审只获得原文、卡片和答案，没有获得实际工具轨迹，因此质疑该检索陈述的依据。

实际回答执行了“周会”检索、收藏原件读取，以及带日期范围的“林澄”检索；最后一项返回隔离库的四篇当前资料。这支持本次可见范围内的检索表述，不能推为现实中不存在后续变化。正式验收驱动现向评审同时提供完整原文、Memory、答案、实际 `{tool, arguments, count}` 轨迹及已核验的四文档语料范围，仍受 20,000 字符入口限制，没有截断证据或修改答案。

补充复核在同一私有库中只执行一次实际独立评审，关闭后台工作并禁止 CLI／飞书访问，没有重新提取 Memory 或重新生成四个答案。351 个产品源码及输入文件哈希与首次入库时一致；唯一排除项是上述验收驱动的评审上下文修改。复核前后逐条核对 Memory、原件和 Memory 任务 JSON 不变，原始报告字节也未变化。补充判决为 **Memory 4/4、回答 4/4，`status=passed`**；首次报告的 `status=failed` 和原判决保留，没有覆盖为初次即通过。

本轮真实租户库共记录 **10 次完成的外层模型调用**：四次提取／审核、四次用户问答、首次评审及补充评审各一次。它们不是供应商 HTTP 请求次数，也未据此估价。此次调整仅修正评审输入，没有修改产品回答或提取提示词。

### 原生搜索探测和限制

额外使用固定 CLI 1.0.85 在同一测试文件夹执行空查询、固定绝对时间范围的创建／编辑／打开搜索。三项均成功，所有实际结果都在合成清单内：创建命中 **4 篇**，编辑命中 **0 篇**，打开命中 **0 篇**。没有将 API 写入和读取转换为人类编辑或阅读事件，也没有用期望结果填补零命中。

该探测额外使用原生文件夹过滤，证明受限范围内的真实搜索传输；它没有验证产品默认全账号发现到 Memory 的完整链路。文件夹发现到归档、修订和 Memory 的链路单独通过。本轮仍未验证首次扫码授权、跨组织可见性、人类操作产生的编辑／打开信号、索引延迟、长期 API 自读污染、15 分钟无人值守定时器或物理设备交互。
