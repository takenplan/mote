## Decision

Central Web remains the complete archive and management workspace. Preserve the sidebar and top bar, original-first reading, separate materials and memories, input sources and outward AI access. Keep quick note in the global top bar; saving or collapsing returns to the same page, reading position and unsent question. The same record uses the same detail from library, source or citation, with an origin-aware return path.

Android becomes one daily home with **Record** and **Ask** as its two primary actions. Materials and memories, discoveries, tasks/calendar, capture/sync and settings remain reachable from secondary navigation. Its current presentation contract declares only `home` as primary, with `navigation: home` and `detail: stack`; trusted layout packs cannot restore the retired four primary tabs. Secondary route identities and capabilities remain available. The four-primary-tab and additional Record-tab prototypes are superseded. Normal background capture/sending does not occupy the home; actionable exceptions have direct repair entries. First use explicitly supports recording locally before connection and deferring permissions and model setup. Exact record/citation readers remain directly reachable from saved records, answers and results.

Mac retains its sidebar, full content/source/Ask workspaces and menu-bar quick entry. Its landing emphasizes Ask, recent conversations and recent content, with compact normal capture/sending status. It does not adopt Android's layout. Closing the main window retains the existing background lifecycle; explicit quit remains separate. Native permissions, local folders, capture and queued copies stay on the device.

Default surfaces show content, necessary status and meaningful actions. Technical detail is available progressively in settings, More, help and diagnostics. Existing capabilities must remain reachable; simplicity is not permission to remove them. Use the agreed warm surfaces, restrained accent, components and platform controls from the actual prototypes, rather than a newly invented cross-platform layout.

The continuation's requirement to match the final source supersedes implementation-only variance D34. Restore light muted and sidebar-muted text to source `#777066`, replacing the previous agent's `#6f695f`. The inventory discloses the five source color pairs below 4.5:1; they are explicit source exceptions, while all other existing text/control contrast checks remain. Do not claim universal 4.5:1 contrast or keep an unapproved color difference under a claim of visual equality.

Use existing original text/images for list previews, not a new summary object. Memory has a detail and searchable/filterable list; an independent view-management product was rejected. Remove the server-directory import UI; preserve file/folder/ZIP intake and their existing archive/preview/recovery semantics. Discovery defaults to the formatted result and moves alternate standard reading into More without changing generation or storage.

The formatted report uses natural content height within the existing opaque iframe. Its sole host-authored nonce script may report a bounded numeric height or a current citation index. Model-authored scripts, event handlers, arbitrary links and network requests remain blocked. The parent verifies the frame, current owner connection, document token and integer index before mapping its own current citation list to the existing exact-original reader. Old-owner and old-document messages cannot navigate; the report never supplies an arbitrary URL or evidence identity. Source badges use the approved numbered tint blocks, including the source's coarse-pointer sizing. This presentation bridge grants no additional reading or write authority and changes no stored report format.

Settings use Models and Services, with service connections, module/model assignment and material processing. Background authorization is presented as automatic processing within material processing, retaining the existing global service/source/content scope and first-enable/change confirmation. Saving a provider does not grant authorization. The ordinary automatic-processing review proposes only existing host-declared connections from saved settings. Preserve every saved source scope, including an empty deny-all list; only the unapproved initial state proposes current sources. Explicit confirmation still uses the existing revision and operation identity. Pause and immediate stop retain their separate existing semantics. Memory/plugin, storage/backup, usage, diagnostics and preferences remain discoverable. Complete the one-action local OCR/ASR managed path, including dependency preparation, model download, start and failure recovery. Download completion must not be represented as service availability. Validate this path using resources controlled by this task, not the owner's existing deployment.

Every save/import/source-sync journey offers optional owner-authored context, separate from originals, quoted material and the owner's own addition. Single-item and source-wide scope must be explicit. Background continuation reuses saved context and must not silently trigger paid historical processing. The owner authorizes completing missing fields, storage, transport and parsing context; a cosmetic successful save is insufficient.

Submitted conversations remain visible after ordinary referenced-material modification or deletion. They retain historical citation identity and a continuation entry; unavailable originals explain their state and are never silently retargeted. Ordinary-update history already satisfies this target. The owner authorizes changing ordinary deletion to retain that submitted history, while explicit privacy erasure, forget and revocation retain their current erasure/restriction rules. Already-erased text cannot be recovered. This does not broaden original access, model-context permissions or expiry policy.

Calendar's target is automatic effectiveness within granted bounds, with no per-item approval queue. Complete events satisfying existing authorization, version and certainty conditions take effect directly. The owner supplies missing time in event detail; missing information, waiting for a device, uncertainty and actual write receipts remain visible. Do not guess a time or silently choose a new device/calendar/scope. The owner authorizes extending the current create-only managed path to update/cancel/complete within the existing authorization, without extending devices or calendars. Preserve target/version checks, idempotency, actual device receipts and host protections; authorization does not establish that implementation or verification has finished.

H11 adds only `POST /api/actions/:id/information` with strict `{version,start,end,timeZone}`. It applies to a current unresolved proposed create/update with a null schedule field and no existing dispatch. Existing non-null schedule strings remain byte-for-byte unchanged, with the existing explicit-zone, all-day and end-after-start rules. Preserve title, location, description, allDay, evidence, related/target identity and semantic uncertainty. A successful save advances only the information version; it does not dispatch or prove a device write. Existing managed reevaluation may adopt it only within a unique effective grant; overlapping/absent/revoked grants, expiry or unresolved uncertainty still block execution. Revalidate the action version, original evidence and related event. An unknown result retains the exact original version/body for explicit retry; a 409 requires reading the exact current event and checking its facts, without changing the payload, resaving a newer version or inventing a successful write.

Chrome's recheck uses the authenticated local bridge to inspect only the saved exact HTTP(S) origins with `chrome.permissions.contains`. It reads no page and requests no permission. Disconnection, multiple peers, busy/timeout/cancellation and changed settings remain unverified. Backup import reports confirmed completed work separately from a potentially written but unconfirmed current record; an error must not imply nothing was saved. Explicitly selecting the same archive again uses existing identity/content deduplication, without a new transaction or automatic retry strategy.

The owner library must show a successfully saved original note even before any model-derived Material exists. The owner-only `/api/library/browse` read projection merges existing captures and published Materials without adding storage, synthetic summaries or a model task. Its signed chronological cursor is complete across both existing sources, normalizes equivalent source timestamps, respects current visibility and invalidates on deletion or generation changes. Deduplication is limited to a complete Material whose exact singleton original is the same readable record; uncertain or multi-original lineage remains separate. Existing catalog consumers keep their contract. Reading a note or browsing it never triggers paid processing.

Reader Ask actions use the existing open-query `anchorEvidenceIds` contract with verified readable originals. Opening an Ask action does not submit a question. The draft, uploaded attachments and return origin remain attached to the current owner connection; changing references must not convert derived Memory prose into user-authored question text or a new authorization grant. Historical/unavailable originals must not silently resolve to current replacements.

For a whole Material, H10 uses its exact `material:mat_…@revision` locator instead of expanding block IDs. Admission and preparation validate the selected time/device scope and existing current read exposure. Subsequent model boundaries and publication revalidate the version and exposure; the existing tools retain any narrower child scope and all original/image authorization checks. The locator seeds navigation to `material_read`, supplies no body and is never citation evidence. Readable partial or asset-only Materials retain their existing coverage and modality rules. Actual delivered pages/originals keep existing disclosure lineage. This is a current-format optional field with no new tables, migration, automatic processing, provider selection or pricing policy.

The existing Web/Mac/Android acceptance-summary JSON files retain their own revisions, dirty flags, generated/native boundaries and uncovered states; they are not a final-candidate rerun. Discovery's safe natural-height default HTML is integrated; the Web report's read-only host citation bridge is being completed to preserve exact references and original returns, with final host acceptance still for the root run to record.

An independent reviewer uses the source inventory established before implementation to check completeness. Validate the changed module with focused risk checks, then run the real three clients in isolated generated profiles and compare each applicable page, dialog and state with its corresponding prototype. Record viewport/screen, theme, language, source, revision, screenshot, differences and pass/fail/untested/Hold. Unit tests and DOM assertions do not prove visual equality; platform-specific layouts are expected to differ exactly as their own approved sources differ.

The inventory separates earlier partial visual evidence from the integrated candidate. Use the original conversation, its accepted source files and already-generated source screenshots to identify the target. Per the owner’s latest direction, do not make website login or publication-preview access a dependency. A source state not actually observed must stay unverified. A screenshot of the prototype is not a screenshot of the product, and neither replaces actual state transitions.

After the UI converges, run the real clients against one isolated Central with generated evidence. Where a journey requires inference, use the owner's required local Codex Server model `gpt-6.1-terra`, record the actual calls and persisted results, and continue the same conversation and citations across clients. Do not substitute another model or fixture answers. Controlled failure injection is labeled separately. The final integrated run follows, rather than replaces, focused module validation.

Use draft PRs, independent code/design review, relevant checks on the final head and the owner's authorized merge path. Verify the remote main commit. Do not approve on the owner's behalf, bypass branch protection, push directly to main, deploy or publish a release.
