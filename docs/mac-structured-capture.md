# Mac Chrome 与微信采集

Mac 对每个 App 分别选择记录时长、保存截图、结构化解析，三项可独立组合或全部关闭。新配置默认只记录时长；加载字段规则、连接 Chrome 扩展和取得系统权限不会自动选择其他通道。

## 采集范围

Chrome 使用随 Mac App 分发的 MV3 扩展，通过限定扩展身份的 Native Messaging 和私有本机套接字连接采集器。扩展不获得中央令牌，也不能调用任意本机命令。仅在 Mote 正在采集、对应 App 已选择内容通道且站点已获明确授权时响应采样请求。

Mac 设置 → 隐私中填写站点完整来源（例如 `https://www.zhihu.com`），点击“准备 Chrome 扩展与本机桥接”。在 Chrome 的扩展程序管理中打开开发者模式，选择“加载已解压的扩展程序”，加载设置页显示的目录；再通过扩展弹出页授权相同站点。安装扩展本身不会开始采集。Dev 包目前以此方式分发扩展，尚未发布 Chrome Web Store 版本。

只有当前前台 Chrome 窗口的活动主框架可采集。扩展检查窗口焦点、标签页、文档身份和站点权限；原生助手独立核对前台进程、窗口与正文区域几何、URL 和遮挡，采样后再次核对。原生辅助功能权限不足、多个身份无法对应、窗口被覆盖或结果晚到时不接纳内容。无痕窗口排除。持续站点授权和手动当前页的临时权限不同。

首批包括知乎回答、B 站视频及保守的通用可见正文块。正文、作者、标题等只保存实际读到的值，导航和推荐不作为主正文。已加载但不在视口内、折叠、输入、密码、编辑区域和被遮挡内容不采集。`visible_window` 始终表示所见片段，不代表文档全文、读完或认同。内容未公开、布局无法可靠判断或预算用尽时保留部分覆盖与缺口。

微信首批适配 macOS 4.1.15，仅读取 `chat_message_list` 中经过隐私过滤的消息叶节点，保留会话名、可确定的群人数、消息块与观察内顺序。控件 ID、遍历序号和本机观察 ID 不作为平台消息 ID。没有可靠发送方、方向、日期或消息时间时保持未知；相同正文保留为不同消息。不会主动翻历史、滚动或操作会话。

## 截图、OCR 与计时

选中截图后，无论结构化成功与否都独立决定保存；未选截图时，结构化失败不会打开截图。每个出现在整屏画面中的 App 都必须允许截图，未知窗口拒绝。画面含 Chrome 时还必须是经过验证的唯一可见 Chrome 窗口；其他窗口或后台 Chrome 无法逐窗验证时拒绝截图。

“使用本机临时 OCR 补充结构化内容”默认关闭。首版只在微信消息区域能由原生助手证明完整可见、未遮挡且身份一致时使用，遮罩在裁切和识别前应用。输入、其他区域和无法证明的范围不作为 OCR 输入。未选截图时临时像素识别后释放，不写图片或缩略图。Chrome 首版使用 DOM，没有浏览器 OCR 回退。

只有独立 `activity` 记录累计应用使用时长，截图与结构化事件时长为零。关闭时长仍保留观察时间戳。浏览器播放状态使用独立媒体记录：结构化开启、时长关闭时保存零时长事实；时长开启时仅对连续、同一媒体且明确播放中的观察计入保守区间。暂停、断连、切换、停止、休眠和失效会中断区间。应用使用与播放区间是两个指标，不能相加。

同次产物共享 `captureObservation.id` 及采集选择，结构化对象通过观察内序号保留顺序。原文先进入本机持久队列，上传策略独立控制；可靠确认后才释放待传原件。重试不重新提取或改变原始身份。

## 中央处理

需要先更新 Central 至包含此变更的版本。Mac 产生 v3 命名字段；浏览器明确标记 `browser_dom`，AX 标记 `accessibility`，OCR 值标记 `ocr`。中央复用安卓已落地的确定性字段材料、媒体区间、检索、原件引用和持久执行器。

自动整理活动是独立的默认关闭功能，启用后仅处理新接纳的授权内容，和 Memory 独立。字段原文可查询不依赖模型或 Memory。重复上传、重启、重建和之后启用不能产生历史模型授权；查询继续只读。现有活动整理优先同次结构化输入；截图独立归档并供按需核验，不承诺自动补充字段未覆盖的图像区域。

## 安装与格式边界

Desktop 本机存储格式为 4。旧格式原样保留并拒绝使用，不自动转换、迁移或清空。安装前用旧版完成待传内容同步并备份；退出旧版，按明确选择重置本机 profile 后再启动新版并重新连接、配置。不要先覆盖唯一可用旧版，再期望新版上传旧队列。Dev 和 Prod 的本地身份及凭据相互隔离；扩展桥接准备只在用户点击时写入对应本机注册。

## 验证与限制

回归使用生成页面、消息、私有临时 profile 和测试中央。真实 Chrome 隐藏进程验证扩展加载、Chrome 启动原生宿主、私有桥接、字段返回和失效拒绝；这条测试的 OS 前台／AX 边界使用生成 helper，不能等同物理桌面权限验证。原生生成 AppKit 窗口另测真实 AX 属性提取及遮挡拒绝。实际全屏窗口已通过未修改的生产几何检查，读取了生成消息并排除了输入区域。此机器普通窗口仍被 Dock 的整屏 CG 窗口范围保守拒绝；AX 命中测试不足以证明它在视觉上透明，因此没有按进程名忽略遮挡。首个 Dev 版本应把全屏作为内容采集的受控验证路径，普通窗口的系统遮挡识别仍是已知缺口；独立时长记录不依赖内容几何证明。

本轮没有第三方微信测试账号、真实个人截图或 live-model 质量验收。真实微信首次读取能力的人工实测见本次会话；生产 helper 的版本兼容与长期行为仍需受控账号验证。飞书、滴答因登录阻塞不在本版范围，Safari、完整网页导入和后台标签页／播放不在首版范围。
