# 配置归属与执行快照

当前生产使用[多用户配置合同](design/multiuser-configuration.md)：操作员选择实例 YAML，每个账号在固定私人目录使用自己的 YAML。两者复用 ConfigService 的读取、稳定监听、校验、diff、revision、原子保存、prepare/publish/rollback；Web 和文件编辑在各自文件上共享同一事务。操作见[服务端配置](server-configuration.md)，选择依据见[统一配置 ADR](adr-unified-configuration.md)。

| 责任 | 权威 |
| --- | --- |
| 实例监听、目录、共享执行资源、媒体进程、可信构建与固定 parser | 操作员实例配置与已有管理员控制，保留重启/迁移边界 |
| 共享模型 | 管理员维护完整资源，个人选择固定引用；不向个人复制共享端点或秘密 |
| 个人模型、价格、处理、Memory、Actions、原件加密、连接器与插件实例配置 | 当前账号 ConfigService 和领域服务；文件路径从认证上下文取得 |
| 原件、版本、任务、策略绑定、授权、回执和外部操作 | 各账号领域数据库，不是 YAML 的替代覆盖层 |
| 采集、隐私、队列与客户端偏好 | 设备本地；Android 采集偏好按部署/账号保存，OS 权限和安装资源仍属设备 |

每份文件有自己的编辑 revision，不是整个实例的个人配置总版本，也不是所有任务的内容版本。相同内容保存不增加 revision 或创建任务。陈旧保存冲突；需重启/迁移字段分别显示已保存值与当前有效值，保存成功不等于资源已重建。

领域拥有 schema、敏感字段、准备、应用与回滚。异步安装不能提前暴露候选权限；同步 publish 一起切换相关有效快照和投影。不可逆取消、重新排队及旧资源退休仅在完整事务提交后执行，避免其他领域失败撤销旧配置已经授予的工作。

私人 YAML 删除秘密即撤回有效凭据；专用页面遮罩草稿仅可按领域规则保留本账号同 ID、同 revision 的秘密。更换 provider/protocol/base URL 后复用自己的秘密需明确确认；个人配置不执行环境变量，实例敏感字段的显式引用保持操作员归属。插件默认值在输入解析时应用，不偷偷补写另一份配置。

模型 lease 固定部署、账号、操作、连接/模型、配置、价格及授权身份，凭据只在受保护的宿主快照中。普通共享模型输出预算、推理和 deadline 调整作用于新准入；真实 transport 或凭据撤回、账号重置/禁用/删除仍 fence 在途发布。普通 logout 不取消已准入工作。持久快照恢复不能静默换模型或借另一账号的秘密，见[配置旅程 ADR](adr-configuration-journey-parity.md)。

Files 和 Memory 保留自身的相关配置指纹与提交检查。无关预设编辑不撤销任务，相关语义/服务变化不能由普通快照规则豁免；已完成结果需明确历史重处理。Memory 的策略版本、原件读取/披露授权、任务范围和成功检查点不能因为 YAML 变更而扩大。当前实现与所选程序的未闭合差异单独记录，不能靠重写指南宣布修复。

有效 SQL 投影为摄取、调度和权限提供已提交策略，不是普通配置来源。业务检查点、来源版本和任务输入是历史，不允许反向覆盖 YAML。旧单所有者 ModelSettingsStore/FileProcessing 等适配器只在其显式 legacy fixture 中使用，不能据旧测试名恢复全局设置 API。

验证分别覆盖 ConfigService 故障、账号隔离、草稿/目录/探测、固定模型与用量、Files/Memory 相关指纹及后台恢复。历史 fixture、真实模型、设备和部署结果保持原范围，当前入口及证据见[配置回归](validation/configuration-parity-2026-10-18.md)和[资源消费者](validation/configuration-resources-parity-2026-10-18.md)。本次文档整理未重新运行这些检查。
