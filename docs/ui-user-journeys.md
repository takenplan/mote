# 用户旅程与 UI：三端模块衔接

2026-10-26，根据所有者的 [UI 讨论与后续选择](https://chatgpt.com/share/6ade4e2a-f24c-83e9-81ff-0cf1ed58cf8f) 整理。一级导航沿用 [UI IA v1](adr-ui-ia-v1.md)；本篇补充之后确认的同步、资料、检索和发现交互。早期讨论中的推荐、原型预选项和末尾尚未回答的选择题，不构成已确认决定。

本篇是设计与验收基线，不是测试通过记录。当前代码可以先提供诚实的未接入入口；没有真实数据、权限或执行能力时，不能展示模拟成功。模拟器、生成 fixture、真机和真实模型的执行结果分别报告。

## 1. 产品原则与端的职责

Mote 是一个个人上下文中心：来源负责采集原始资料，Central 负责归档与理解，人和已授权的 Agent 使用这些上下文。采集输入与上下文输出分别管理。它服务一个所有者，多个设备和 Agent 共用这一份个人上下文。

- **智能默认，按需干预。** 在现有授权范围内，检索、主题组织、相关资料选择由模型完成；不要求用户先选 Memory 类型、检索范围或一组资料才能提问。筛选与精确限制按需提供。
- **记录与对话分开。** 保存记录是确定性的持久化操作，不等待 AI；问一问是独立的完整对话。对话内容转为记录需要用户明确保存。
- **结果与异常优先。** 平时展示内容、必要状态和少量发现；队列、批次、执行详情、模型参数逐层展开。
- **数据控制仍由用户决定。** 删除、对外授权和扩大采集范围需要明确选择；已有同步和保留策略不能被一次清理操作悄悄改变。
- **原始证据优先。** 原文、用户批注和模型结论各有身份；状态和引用来自稳定 ID、实际回执与可读证据，不按标题、关键词或相近时间猜测关联。
- **共享视觉语言，保留平台职责。** 沿用纸色与石墨表面、克制的紫色强调、既有控件和原生交互。说明放在首次引导、帮助、错误及重要选择旁，日常页面保持简洁。

| 端 | 一级入口与默认页 | 主要职责 | 次级入口 |
| --- | --- | --- | --- |
| Central Web | **总览**、资料库、数据来源、AI 接入；默认总览 | 全局状态、全部资料与记忆、来源管理、对外授权 | 全局搜索／问一问、发现历史、活动与执行详情、设置 |
| Mac | **工作台**、内容、来源、问一问；默认工作台 | 本机采集、文件与来源、记录、同步、本机问答 | 菜单栏快捷操作、同步与活动、设置；全局管理进入 Central |
| Android | **首页**、资料、问一问、来源；默认首页 | 随身记录、后台采集、同步、资料阅读与问答 | 全局 **+ 记录**、同步与上传、设置；详细状态不占底栏 |

显式深链接、导航返回、已保存的目的地与未保存草稿继续有效。调整展示层不能清空草稿、改变授权或启动采集。iOS 尚无客户端和冻结的信息架构。

## 2. 按模块串联页面与状态

### A. 首页、采集与同步

Android 首页顶部只用紧凑的两行，分别回答「是否在采集」和「是否在发送」。状态随首页滚动离开，不在资料、问答、记录等页面常驻或悬浮。点击采集行进入采集详情，点击同步行进入同步与上传详情；正常状态下不把一排开停按钮放在首页。

常规等待、批量条件未满足、等待 Wi-Fi、主动暂停均是正常状态。只有需要处理的严重异常才跨页面提醒，例如采集意外中断、凭据失效或无法继续本机保存。提醒直接指向实际问题；不得用笼统的「一键修复」更改来源、隐私或资料归属。

| 页面 | 内容与操作 | 下一步 |
| --- | --- | --- |
| Android 首页状态 | 采集状态；发送状态、待传量及必要的最近时间 | 采集详情，或来源 → 同步与上传 |
| 来源 → 同步与上传 | **当前任务 / 上传历史** 两个视图 | 当前任务的等待原因与重试；历史的日期 → 批次 |
| 上传历史 | 日期在列表内展开；使用真实接收与未确认数量 | 独立批次详情 |
| 批次详情 | 时间、来源、确认数量、未确认数量、大小和实际错误 | 来源／单条记录 → 原件与接收回执 |
| Mac 工作台 | 随手记、导入文件、添加来源优先；采集、连接和发送为轻量状态 | 本机来源详情或同步详情 |
| Central 总览 | 实际来源状态、处理进度、需处理问题、最近内容和少量发现 | 对应来源、资料、发现或活动详情 |

一条记录多次重试后成功，已接收数量只计算一次。没有批次或原件映射时说明暂不可用；不能根据展示日期拼出虚构批次。Central 收到不等于处理或索引完成。

### B. 资料、记忆与阅读

资料的主视图为 **我的资料 / 我的记忆**。资料承接用户保存的内容与正式资料；记忆承接 AI 从证据中形成的理解。洞察不混作永久事实。

Android 的已确认目标是把本机与 Central 作为同一资料列表中的位置和状态，提供按需位置筛选。同一份资料须按稳定 ID 合并，不按标题和时间猜测。当前后端尚未提供的合并、历史或字段应明确说明，不能把位置跳转包装为已合并。

| 层级 | 默认展示 | 深入操作 |
| --- | --- | --- |
| 我的资料 | 主动记录与导入资料容易找到；自动采集按 Session／日期聚合 | 按来源、位置或时间筛选；展开原始记录 |
| 资料详情 | 原始文字、图片、录音或文件在前；本机／Central 与处理状态清楚 | AI 整理结果、关联记忆、版本与接收依据按需展开；问问 AI |
| 我的记忆 | 模型自动组织的主题视图，同一记忆可属于多个视图 | 原始证据、相关主题与已有有效时间信息 |
| 搜索结果 | 用户表达要找什么，系统检索已有授权内容 | 打开原文或进入完整问答；保留返回位置 |

离线仍可阅读本机已保存的资料；Central 查询不可用时说明限制。AI 不能把未读取、已删除或超出当前授权范围的证据当成可用上下文。

自动纠错、冲突消解和修改传播暂缓。讨论中曾提出「直接编辑并保留历史版本」，所有者没有确认该具体方案；不能据此新增编辑或派生记忆变更政策。

### C. 记录、搜索与完整对话

Android 全局 **+ 记录** 直接打开统一编辑器，不先弹记录类型菜单。文字、照片原件、图库图片、语音和文件使用同一草稿；不强制标题、分类和标签。明确保存后本机持久化并返回原页，不等待识别、上传或模型整理。失败保留输入和附件，页面重建保留草稿。

系统分享先进入编辑器，由用户确认保存。分享原文、引用的对话和用户自己的补充分开记录；保存第三方内容不等于用户认可其中的指令或观点。

从资料点击 **问问 AI** 进入独立完整对话，自动携带该资料作为重点上下文，模型仍可在已有授权内寻找其他相关内容。只有用户明确要求「只看这份资料」时，才使用严格范围。页面展示实际引用，不能把检索锚点冒充额外访问授权。

当前协议以 `anchorEvidenceIds` 表达参考记录，以 `evidenceIds` 表达严格范围，两组非空选择互斥。省略字段沿用对话选择；显式 `null` 只清除对应的一组。新指定其中一组会清除另一组，每轮受理时固定解析后的选择。参考 ID 不预先提供原文，模型须通过现有证据工具实际读取后才能引用。

Central 保留全局搜索／问一问入口、搜索与问答模式和完整对话工作区；Mac 保留本机问答与历史。切换端继续对话时，当前资料锚点或明确范围仍可见。真实读取继续受隐私、删除、版本和授权边界控制。

### D. 数据来源与按应用配置

Central 的 **数据来源** 管输入：设备、文件、云端连接器和将来的外部 MCP 资源；**AI 接入** 管输出：授权外部 Agent 使用上下文。设备配对属于输入，即使底层复用凭据服务，也不放进对外 AI 授权流程。

Mac 来源按屏幕／应用活动、文件／文件夹、Coding Agent、本机日历及其他来源分组；需要处理的问题可直接指向来源。云端来源进入 Central。一次性导入的结果在内容页阅读。

Android 和 Mac 的按应用配置使用相同的通道语义：**应用时长、截图、结构化内容** 三个独立勾选项。默认设置、沿用默认、单独设置、显式全部关闭分别呈现。

1. 来源 → 按应用配置，先看到默认值和应用列表。
2. 搜索应用，或选择全部应用、单独设置、字段规则、需处理的范围。
3. 进入应用详情，查看实际已选通道、安装版本、可用字段、规则来源和适用条件。
4. 修改当前页面草稿；详情返回、筛选切换、刷新或页面重建不覆盖已改值。
5. 明确保存后生效；只保存配置不改变原有采集开停意图。

有字段规则不代表已经成功读取。版本不符、版本未知、无权限、浏览器扩展与站点授权等情况各自显示实际条件。界面不得把 Android 能力套在 Mac 读取器上。采集边界见 [页面内容采集](ui-page-capture.md) 和 [采集与上传](collection-and-sync.md)。

### E. 发现与记忆展示

已确认的发现方向是：**首页精选 + 二级发现历史**，不新增一级导航；先展示结论，依据可一键展开；记忆由系统自动组织为多主题视图，用户无需维护分类目录。

有充分依据的重要洞察可以在用户授权后通知，普通发现只在 App 内。没有新发现时不为了占位生成内容。通知触发门槛、去重算法、频率和择时尚未确认，本次不把原型的预选值写成产品默认，也不据此增加推送流程。

### F. 授权、停止与删除

智能默认不扩大采集范围，也不代替对外授权。按用途推荐权限的方向已确认，但 MCP 详细交互已暂停；现有连接和授权能力继续可用，未实现的能力只作清楚标注的占位。

暂停屏幕采集、暂停某一来源和暂停全部发送是三种独立意图。暂停和离线保留已保存资料；暂停全部发送不等于停止本机记录。恢复仍遵循原同步策略。

用户主动删除须能选择实际影响范围，并看清本机副本、Central 归档、来源原件及派生内容的关系。删除当前资料、停止持续同步、断开来源和删除来源历史不能捆绑执行。已有保留策略继续有效；离线的远端删除不能提前显示成功。具体删除选项、编辑历史及清理传播尚需沿既有产品能力逐项设计和审查，不能从讨论中的示意按钮推导出新的破坏性操作。

## 3. 跨模块完整旅程

下面的路径用于串联验收。每一条都从用户可见入口进入，最终观察保存结果、真实消费结果或清楚的受限状态；只打开页面不能算旅程完成。

| 旅程 | 页面与模块顺序 | 必须观察的结果与返回 |
| --- | --- | --- |
| J1 首份记录到可用资料 | Android 首页／任意主页面 → + 记录 → 明确保存 → 我的资料 → 原文详情 → 同步与上传 → Central 资料库 | 本机先保存；连接与发送条件满足后获得真实 ACK；处理状态单独呈现；详情返回原位置。无 Central 也能完成本机保存。 |
| J2 采集配置到原始证据 | 来源 → 按应用配置 → 应用详情 → 修改通道／规则 → 保存 → 采集详情 → 聚合资料 → 原件 | 继承与覆盖不混淆；全部关闭可持久化；保存不擅自开始采集；实际运行受权限和读取器约束。 |
| J3 发现待传与恢复同步 | 首页同步行 → 当前任务 → 等待／失败原因 → 对应连接或来源处理 → 返回当前任务 → 上传历史 → 日期 → 批次 → 记录 | 正常等待不报故障；本机内容保留；只对实际成功 ACK 计数；原件和回执一致；返回保留历史层级。 |
| J4 找回资料并提问 | 我的资料／全局搜索 → 输入意图 → 资料详情 → 问问 AI → 引用证据 → 返回资料 | 当前资料为锚点，模型可检索其他已授权上下文；显式严格范围另行生效；原文可追溯；问答和资料不互相覆盖。 |
| J5 对话沉淀为记录 | 完整问答 → 选择保存内容 → 审阅并补充 → 明确保存 → 资料详情 | AI 回答、引用和用户补充分开；没有明确提交不产生记录；保存后不改写原回答。 |
| J6 首页发现到依据与追问 | 总览／首页精选 → 发现详情 → 展开依据 → 原始资料 → 问一问 | 结论与原始证据分开；显示实际可读依据；没有后端能力时说明限制；不把通知算法当成已完成。 |
| J7 Mac 日常工作 | 菜单栏／工作台 → 随手记或导入／来源配置 → 内容 → 同步状态 → 问一问 | 菜单栏和主窗口复用草稿及状态；关闭主窗口保留已有后台生命周期；全局管理可进入 Central。 |
| J8 来源与对外 AI 接入 | Central 数据来源 → 添加／配对 → 第一份资料 → AI 接入 → 已有授权配置 → 核实实际连接 | 输入与输出位置清楚；生成配置不等于 Agent 真正连通；尚未实现的用途向导不能显示成功。 |
| J9 草稿、暂停与恢复 | 编辑记录／采集草稿 → 导航或 Activity 重建 → 返回草稿 → 保存 → 暂停发送 → 继续本机记录 → 恢复发送 | 输入、附件和修改保留；暂停范围准确；没有重复记录或重复成功计数；恢复遵循既定归属和策略。 |
| J10 清理与数据控制 | 资料详情／来源详情 → 查看现有策略 → 选择已有清理或停止操作 → 核实影响范围 | 不能用本机清理暗中删除 Central 或来源原件；断开与删除分开；未实现的范围操作不产生外部效果。 |

## 4. 当前实现与待完成边界

早期 IA 已建立三端主导航、Android 统一记录编辑器、Mac 工作台、Central 双视图资料库和问答工作区。PR 232 补充 Android／Mac 的按应用配置列表与详情。后续 UI 调整应以本篇确认的旅程连接这些模块；接口缺失不能由假数据或名称更换掩盖。

| 范围 | 实现约束 |
| --- | --- |
| Android 首页与同步入口 | 首页顶部展示可点击的采集／同步两行，更多控制收在详情。来源的「同步与上传」和首页同步行进入同一二级页面，提供当前任务／上传历史两个视图。 |
| Android 上传历史 | 展示本机有上限的操作日志中实际保留的最近上传结果，可分页查看时间、结果、原因、字节、耗时和 HTTP 状态。当前不是持久化的日期／批次／单条原件回执账本，没有虚构批次或成功数量；完整分层历史仍是目标。 |
| Android 资料双视图 | 已提供我的资料／我的记忆入口；记忆进入已有 Central 原生记忆页。资料仍分别浏览本机与 Central，并明确显示这个限制；同 ID 自动合并和跨位置统一筛选尚未实现。 |
| 问答资料锚点 | Android 记录提问默认参考记录并自动检索，可明确切换为只看该记录；Central 对话显示对应原文与清除入口。主机在准备、模型调用和发布时沿用真实 reader 的隐私／来源可见性、时间、设备、内容指纹和删除检查；锚点作为运行与历史依赖保留。 |
| 输入与输出 | Central 数据来源／设备页面进入独立设备配对页，AI 接入页只呈现现有 MCP 授权，连接清单按各自权限类型展示；凭据、授权与撤销语义沿用现有能力。 |
| Central 发现 | 首页精选链接携带确切洞察的 `runId`；二级洞察页按 URL 打开该结果，保留历史选择和前进／后退，不把阅读入口默认变成新建表单。缺失结果明确说明不可用；通知策略和实现暂缓。 |
| 删除与编辑 | 保留当前明确边界；新增破坏性范围、版本与派生传播必须独立设计和验证。 |

以下项目在分享中尚未定稿：首次使用 E1 的统一／分端策略、统一 AI 行动体验、隐私与生命周期的完整流程、插件功能的普通用户入口，以及 iOS 定位和 IA。保持现有可用流程，不把最后一轮建议当作所有者选择。

明确暂缓的项目：MCP／Agent 专属向导与一键安装等接入细节；记忆自动诊断、纠错及冲突传播；洞察通知的触发、去重、频率与择时。占位需说明限制，不新造授权、执行或成功状态。

## 5. 验收方式

按 [测试说明](testing.md) 使用生成资料、隔离 profile 和专用后台模拟器。优先连接 J1／J2 的最小真实路径，再检查状态返回、离线、重试、重建与消费者。计划收敛后执行一次受影响候选检查，不因文档更新重复未受影响的成功检查。

- Android 模拟器：实际导航、编辑与保存、采集配置草稿／重建、同步二级路径、资料／记忆入口及受限状态；通过应用自己的安全渲染获取生成页面，不采集个人屏幕。
- Mac Electron fixture：真实 renderer／preload／IPC、应用设置持久化、菜单栏与工作台草稿、内容／问答返回；采集平台边界使用的替代实现单独注明。
- Central 生成 fixture：实际来源与 AI 接入页面、资料／问答锚点和引用、同 ID 与真实 ACK／处理状态的消费者。
- 真机采集、真实第三方应用兼容性、外部 Agent 实际连接和真实模型判断各自需要独立证据；生成响应和模拟器通过不能替代这些结果。

发布按 [独立发布架构](release-architecture.md) 和 [发布流程](releasing.md) 处理；仅对实际改动并通过对应候选检查的端发布 Dev 产物。具体版本、提交和执行结果写入本次 PR／发布说明。
