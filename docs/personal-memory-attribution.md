# 用户表达、代办任务与项目归属

个人上下文优先于通用知识提炼。模型先辨认说话者、被描述的人、用户与材料的关系，再选择保存层级。渠道只决定读取格式与证据分组；来自 Kimi、Codex 或 Claude 的会话不自动等于编码经验。没有关键词意图分类器。

## 链路与存储

原始事件归档 → 会话 Material → 模型提取 → 独立审核 → 精确证据/权限/版本校验 → 原子生效。当前流程无需用户逐条确认；显式纠正和历史重做保留，见 [准入](memory-admission.md)。2026-10-07 新增的统一声明与持续处理见 [归属 ADR](adr-material-attribution.md)。

导入时已有的可选说明同时提供格式和作者背景，按该次新增原件及文字所声明的范围传递；不会按关键词把整份来源变成本人。个人 v4 引入的解释规则由当前 v5 延续：将说明与连续原件一起解释。主要为本人日记、少量通话的说明，在正文支持日记范围时可建立主叙述者对应，默认 unknown 不要求逐份再确认。多人发言、引述、转述和背景声音仍逐项限定。真实对应未知时保留有用的来源限定观察；Ask 使用当前原件核对主体、时间和计划状态。新版本、未来默认升级及旧任务边界见[上下文读取 ADR](adr-memory-context-reading.md)，个人 v3 定义见[有限个人 Memory ADR](adr-bounded-personal-memory.md)。

当前内置个人配方 `mote.personal-memory@5` 组合提取 v3 与审核 v5，在保留 v4 上下文解释责任的同时采用 `range-evaluation@1`。每个目标范围须完整评估并经过独立审核，再由模型择要保存；没有候选数量配额，未选细节仍可从完整原件检索。新库普通默认使用个人 v5，采集默认追加日常事件 v2；具名升级仅替换精确匹配的内置默认组合，旧固定定义、已授权旧范围、来源覆盖和自定义选择保持各自边界。详见[范围评估 ADR](adr-memory-range-evaluation.md)与[策略组合](memory-strategies.md)。

新 Memory 任务区分必须评估的目标范围和可补读的解释范围。提取与独立审核模型可按具体缺口，用只读工具读取同一任务已经授权的原件开头、续文或其他相关段落；不必读取全部目录，不开放整库，也不让上下文产生独立候选或覆盖。事件年份可由明确回顾区间与连续叙事支持，需同时保留时间框架和局部事件引文；录制/作者日期、事件时间与导入日期分别解释。猜测、计划、未见后续和含混月日继续保留。

- 原始归档：保留采集到的正文、角色、来源、会话、时间及项目元数据；不承诺采集未获得的原始附件。
- Material：保存连续会话和版本，传播已知的项目名、工作目录、仓库标识与分支。模型读取任意证据段时都能获得结构化项目上下文。
- 提取：模型逐条输出 `domain=personal|coding`；同一 Agent 会话可产生个人记忆、编码经验或任务线索。只有 coding 条目携带编码适用范围。
- 审核：检查说话者、引文中的第三方身份、主观与客观边界、项目和时间，以及证据支持；不能仅因用户表达日常、重复、不专业就删除它。
- 保存：沿用现有 `memories` 存储和 `admission.layer`。个人记忆与编码经验进入 `memory`；任务线索使用 `observation`，通过已有事件与资料视图和 `memories(layer=observation)` 按需查找。不增加第三套数据库。
- 使用：默认记忆页、开场记忆、记忆目录及长期整合排除任务线索。线索引用原始会话证据；若原文提供产物位置，陈述中保留该位置。没有位置时以证据引用为入口，不伪造附件、链接或新副本。

任务线索是“知道有这么件事”的简短入口，不是任务产物摘要。无需每条工具输出或每个分段都产生线索，零输出有效。本次不新增产物全文索引、自动采集附件或持久化任务分类器；保持现有资料读取能力。

## 保存边界的例子

1. 用户让 Kimi 转写一段第三方访谈：保留原文，必要时生成 observation“请求转写某访谈，结果及产物位置见证据”。不把受访者的定价观点提成用户经验、偏好或编码决策。用户后来明确说材料与自己的课题有关，记住那条个人关联，而非整份材料的结论。
2. 用户连续两天表达“会议很多，感觉没推进，很累”：保留两次带时间、原文引用的主观经历。可以在整合中关联这些经历，但保留各次证据，不用一句永久性格标签取代它们。重复发生不是传输重试；只有同一证据的幂等重试才应避免重复落库。
3. 用户在日记里写“用 Agent 做了功能，报错后改了改，觉得能用了”：原件保留，必要时生成简短 observation。项目名、session 范围、本人确认改过，以及“方便以后排查”的泛泛理由，都不足以把开发经过变成具体技术经验。没有原文支持时，模型不得补造故障机制、修复方法或测试结果。
4. 同一开发记录也写了反复调试的烦累、作品第一次被家人使用的开心：这些个人感受和意义可以保存，开发经过作为理解它们的背景，无需可迁移的技术结论。另有原文明确说明问题机制、处理决定及其取舍，或表达有范围的工程偏好时，可以保存 coding Memory。未测试的决定或假设可以如实保留，不能冒充已验证修复。

上述边界通过共享模型政策在提取、独立审核和整合中执行，不通过正文关键词或手写语义评分分类。普通开发事件线索沿用 `domain=personal`、`layer=observation`，不为套进 coding 结构而伪造 decision/pitfall。

## 项目身份

`projectIdentity` 区分 `workspace`、`session`、`unknown`。采集器有 cwd 时记录 workspace，否则会话兜底。中央可识别旧采集器的精确 provider/session 哈希兜底；不从会话正文或文件夹名字猜仓库身份。缺少可确认身份或元数据冲突时标为 unknown。

Material 及每段模型证据保留该标识。记忆的 `scopeRefs` 保存来源项目名和身份状态，界面明确标为“会话项目”。实际结论的项目、模块、阶段和边界写在 statement/applicability；正文讨论的另一个项目不覆盖来源仓库身份。明确 session/unknown 或已识别的旧会话兜底不能保存新的 project 范围编码候选。旧的无身份状态、自定义项目键契约仍兼容；不自动猜测或合并它们。

## 升级与验证

Coding recipe 升级到 5，Material schema 到 3；既有资料在该来源重新整理时从归档重建项目上下文，不能沿用缺少元数据的旧增量基线。身份发生冲突时重新生成资料版本并使旧证据失效。旧记忆不按新提示词直接批量改写或删除；后续提取与审核使用新政策，版本变化沿用既有失效机制。安装本 PR 本身不重置资料库。

生成夹具测试覆盖混合语义输出、任务线索与默认记忆隔离、重复经历、用户纠正、项目身份传播及增量归属变化。`node --import tsx scripts/test-personal-memory-live.ts` 是单独的可选在线模型检查：只使用临时库和生成文本，执行真实提取、独立审核与结果评估；不读取生产资料或截图。物理设备采集与生产历史重提取需要分别报告，不能由夹具结果代替。
