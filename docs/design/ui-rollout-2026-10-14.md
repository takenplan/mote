## 逐页视觉验收门槛

所有者进一步明确：每一个页面都必须用视觉能力核对实际画面，符合第五轮预案才算通过。代码、构建、DOM、尺寸断言和自动截图均不能代替视觉验收。

1. 按当前产品列出所有页面、二级设置、资料类型、详情、弹窗及相关状态。旧入口仍可访问时也纳入清单；当前未安装的第三方界面和系统权限页面另记边界。
2. 使用生成资料和隔离环境，核对最终产品输入。截图前确认实际内容、空状态或限制已经加载完成；记录真实 producer、构建、APK 或资源身份和原图 SHA-256。局部修改后，受影响画面必须重新构建和取证；未受影响的既有画面只有在源码、资源及消费者影响核对证明等价时才可保留，不得改写为新构建身份。
3. 逐页实际查看图片，核对颜色、字体、线性图标、动作强调、表面、边界、分隔、排版密度，以及职责、完整限制、来源、时间、状态和返回位置。平台例外需有预案中的角色依据。
4. 中英文、常规与窄屏、大字体或真实缩放按计划覆盖；长页须补足中部、末端、内滚动和展开区域，不能用首屏代替整页。相关运行、失败、草稿、输入法与生命周期状态另有实际旅程。
5. 每个必验页面／状态／条件关联到已实际视觉检查的原图和结论。重复、失败尝试和历史参照可保留，但不算已验收；不能由图片哈希、几何断言或模型分数自动填入通过。
6. 缺图、未看、与预案不符或未解决问题均阻止完成验收。修复后重新构建、采图、视觉复验并重跑受影响检查，逐项闭合后才能合并与发布。

通过条件为：必验页面与状态全部覆盖、实际视觉核对符合第五轮预案、相关操作旅程通过，且没有未解决的偏差。单张首屏通过只代表该画面通过，不代表整页验收完成。台账明确区分通过、失败、未查看和证据缺失，并保留失败画面及其修复后的对应关系；不得修改预案来迁就实现。

视觉核对针对设计与可见信息；保存、原文、返回、草稿及授权等行为仍由实际旅程验证。生成界面通过不代表物理设备、真人理解或真实模型验收。

逐页复核还包含原生默认控件：Android 主题颜色通过同一 token 生成器的 XML 输出接入，Mac 计量条显式使用蓝色数据角色。来源规则的长选项沿用完整既有翻译，窄窗补充自然换行的当前选择说明。DEV 关于页沿用手动下载安装职责，隐藏该分支不提供的自动更新渠道和专用于自动更新的验签说明。

## Supersession

- **KEEP**：原信息架构、权限、采集与发送意图、处理范围、保留政策、原文、来源与时间、草稿保护和原任务返回。Android 阅读窗口关闭后重建保持关闭的回归保留。
- **CHANGE**：将第五轮公共视觉角色覆盖至此前遗留的设置、管理和状态组件；窄屏排版、长说明节奏及页脚空间按实际可见尺寸适配。
- **REMOVE**：无角色依据的暖色辅助表面、混用边框和圆角、遮住内容的固定页脚预留、描述已移除功能的过期存储文案，以及 DEV 手动下载分支中的自动更新专属说明。
- **EXCEPTION**：真实错误、限制、处理状态、采集范围和数据去向继续可见；原生系统界面不要求像素相同。完整说明可以通过具名展开项访问，原文不缩减。
- **UNKNOWN**：物理设备、真实个人采集、真实账号和模型、真人审美及完整无障碍认证，不能由生成 fixture 推断。

本次没有新增权限、保留、发送或处理政策，也不把布局分组用于语义分类。源码、构建、生成资料界面与发布身份分别核验，实际结果见 [落地验证](../validation/ui-rollout-2026-10-14.md)。
