# Original Web recording controls through owned connectors

This is the finite R-CONNECT/R-ARCHIVE consumer assigned by the parent, not a
replacement recorder or an accepted whole M13 release. The original
`#/connections/recordings` entry, `RecordingConnection` form, local date drafts,
source declaration, explicit intake controls, failure retry and archive navigation
remain. Native/bearer legacy characterization retains its existing branch.

The Web branch chooses a saved M04/M10 connection ID, then keys the view by its
account credential and connection generation. It uses the existing masked
connection editor and M09 check/enable/pause/stop actions. Neither a provider alias
nor a user ID supplied by the browser selects execution authority. The small
`sourceIds` inventory addition reads only existing `connector_sources` rows for
the authenticated owner and exact instance; it supplies canonical history source
identities without opening an adapter, creating a source or probing a provider.

The thin original-form adapter sends connect/select/retry to existing M10
operations and sync/disconnect to their existing routes. It reads the actual M05
task ID and checks the original signal after every await. Original Save and start
acknowledges the source context and selection before submitting sync. The sync
sub-operation uses the explicit command ID plus `:sync`; transport recovery never
rediscovers an operation by inventing another ID.

A small browser recovery receipt holds only the original command options and
operation ID. Its key pins origin, deployment, owner, credential, instance and
generation. It is not a task store, provider credential, grant, scheduler or second
backend. It remains until terminal task outcome and owned status are read. A lost
admission ACK or task poll exposes the established explicit retry control, including
after React reload. That control resubmits the same M05 identities and complete
payload; it never refreshes an old authority under another account. A different
pending command cannot silently replace it. Terminal rejected/cancelled outcomes
release the receipt for a later explicit action.

Failed-stage retry sends `operation:'retry', payload:{resume:true}` to M15's frozen
seam. It skips discovery and already archived transcript/media checkpoints. The
empty retry payload's existing reset-only behavior is unchanged.

Current-selection checkpoints use M15's signed opaque cursor and display the
separate transcript/audio facts. They are not history. Recording history uses
canonical source IDs with the existing Files opaque pages; the original capture
entry reaches `FileDetail`, including authenticated M03 bytes, corrections,
speaker names, acoustic clips and the existing full tar export. No current page is
presented as the entire archive and no missing totals are displayed as zero.
