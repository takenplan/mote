# UI 反馈续迭代：页面职责、原生一致性与有效预览

用户看过上一轮 HTML 后认可总体方向，但指出三个问题：部分截图未显示加载后的内容，中央 Web 设置出现新记录入口，Android 的风格违和且不统一。本轮用 1～2 次生成者 / 独立评估者反馈循环修正，保留原来的四项及首次理解指标。

## 固定评估合同

原五项继续采用 [原量表](ui-iteration-evaluator-2026-10-13.md) 的 0～10 尺度，分别报告，不能通过增加总分或改权重抵消缺口。此前 D2 / R8 分数是当时的模型评价；用户反馈和复查可推翻其证据或暴露漏验，不把旧分数自动带到当前构建。原生 Originality >7、Design quality ≥8、Craft / Functionality / 首次理解 ≥8.5 仍是努力与接受目标，不能为了得分保留用户认为违和的设计。

追加两项，当前接受目标为各项 ≥8.5：

| 追加项 | 要判断的行为 | 3 / 5 / 7 / 9 分锚点 |
| --- | --- | --- |
| 页面职责与任务聚焦 | 页面标题、主动作、帮助和空状态是否围绕进入目的；跨页面动作是否有当前任务的明确理由；设置草稿、取消与返回是否可理解。 | 3：主要任务被无关动作干扰；5：主要路径可用但仍有混杂；7：职责清楚、有少量歧义；9：常规、空、错误和返回状态均聚焦且可恢复。 |
| 视觉一致性与平台适配 | 同类字体、间距、色彩、圆角、图标、控件和状态是否使用一致角色；Android 是否像协调的原生应用；品牌差异是否帮助阅读和操作。 | 3：多套冲突模式；5：局部统一而关键页断裂；7：主要页面一致、有少量例外；9：跨页面与窄屏 / 大字体均协调，例外有清楚理由。 |

0 表示目标无法成立，10 表示约定检查矩阵中没有观察到缺口。新项不是偏好“所有控件都一样”：导航、主要动作、表单和阅读区域可采用不同角色，必须形成同一个系统。

预览有效性作为交付硬门槛而不新增美学分数：当前场景必须有明确目标页、已完成的内容 / 真正空状态 / 明确限制，以及没有挂起的 Suspense 或读取状态。PNG 可解码、路由已变化或标题已出现都不够。加载或失败场景如需展示，必须按该状态单独标注；不能冒充完成页面。对话框片段必须明确标为片段，优先展示应用自身完整窗口与真实父页面。

## 用户旅程与范围

Web 设置与子页保留设置、验证配置、保存、取消、返回和有关的维护操作；不混入随手记或首页的“开始记录”叙事。配置模型时保留用户带入的原任务返回上下文；纯设置访问不能虚构一个提问 / 记录任务。现有存储恢复属于维护职责，不按普通资料添加入口删除。

Android 保留 Home / Content / Ask、四个平等保存动作、已保存原文、来源 / 时间与实际处理状态。统一 Home、内容、随手记、原文、Ask、设置和连接页面的原生表面、类型层级和触控角色；不照搬桌面纸页，也不迁移 UI 框架或加入新依赖。

第一轮独立复查发现 Android Settings 还保留旧采集 / 同步仪表盘，普通笔记的原文父页仍使用截图专属说明。第二轮将原有采集开始 / 暂停和同步控制放入既有 Home 来源 / 同步区域，Settings 仅保留配置与维护；整体采集暂停与屏幕范围暂停仍是不同操作。原状态控件在 Home 初始化，保留权限预览、明确开始、取消和即时反馈，不用跳过绑定隐藏故障。原文父页按实际已有来源显示标题和日期浏览说明，查询与筛选范围不变。Mac 也隐藏设置族的通用添加记录主动作，保留其他页入口与原生菜单、草稿确认和返回。

最近的现有模式是 [行动优先客户端](../adr-client-action-first.md)、[客户端导航](../client-navigation.md) 与 Slate 配色。Android 的角色化控件、分组与视觉体系参考官方 [Material Components](https://developer.android.com/design/ui/mobile/guides/components/material-overview) 和 [Settings](https://developer.android.com/design/ui/mobile/guides/patterns/settings)。官方规则作为视觉参考，不自动取代产品已接受的导航、维护或权限责任。

| Supersession 分类 | 处理 |
| --- | --- |
| KEEP | 原五项标准、已有功能和目的地、原件 / 处理边界、权限、明确开始采集、离线保存、草稿 / 返回、发送与保留政策；Mac 已接受方案作为参照。 |
| CHANGE | Web 设置的上下文动作与未登录叙事、Android 的统一原生呈现、截图等待与状态证明、当前 HTML 场景供给和新增两项评估。 |
| REMOVE | 设置中与当前任务无关的记录入口；未完成加载却当作完成页面的证据；未注明边界却按整屏展示的对话框片段。 |
| EXCEPTION | 明确带入的原任务返回、配置测试与存储维护仍属相关操作；平台控件可以遵循不同角色；真正空状态和限制状态可作为有效场景。 |
| UNKNOWN | 真人理解、物理设备、真实采集 / 模型 / 外部账号、完整无障碍效果继续单独报告。 |

## 轮次与验证

先独立诊断当前截图和产品状态，再生成第一轮。评估者实际操作运行中的生成界面、审图并反馈；有缺口时第二轮修正，再基于最终构建重验。评估者不编辑产品，自动脚本不打分。

高风险组合：设置 hub / 模型 / 隐私 / 存储子页与已登录 / 未登录 / 失败 / 慢加载，常规 / 窄屏、中英文；Android 设置 / 编辑 / 原文的风格连续性，320 dp / 130% 字体与真实 IME、草稿、原文回读和 Activity 重建。保留用户真实路径，针对本次已确认失败加入持久回归。

所有 UI 测试后台执行，只用生成资料；Android 使用专用无窗口 AVD 与应用自身 View 绘制，保留 `FLAG_SECURE`。受影响组件和消费者通过标准 `npm run check:affected` 检查，原生构建、模拟器、模型和实机结果分别报告。旧轮次不改写为本次已验；无效旧截图明确排除，保留其历史来源和原因。
