# 三端共同美术风格：五轮候选

用户明确认为上一轮 Android 仍然丑、文字堆叠、分隔和按钮边界不统一，并要求三端拥有共同美术风格，调研后再迭代五轮，每轮记录为候选。上一轮模型的美学接受不是当前依据，用户尚未选择新方案。

## 调研与共同方向

[Linear 官方重设计记录](https://linear.app/now/how-we-redesigned-the-linear-ui)展示了通过共同界面框架、表面和文字层级降低噪声、提高导航密度的实践。[Fluent 排版](https://fluent2.microsoft.design/typography)与[布局](https://fluent2.microsoft.design/layout)说明跨平台可以共享角色、节距和对齐关系，同时适配平台尺度。[Android 主题](https://developer.android.com/design/ui/mobile/guides/styles/themes)、[设置模式](https://developer.android.com/design/ui/mobile/guides/patterns/settings)强调颜色、字体、形状、图标的共同体系及简短设置说明。参考这些原则形成 Mote 的共同体系，不复制其他产品的页面或品牌。

同时检查了较新的官方实践：[2025-05 Androidify 的 Material 3 Expressive](https://android-developers.googleblog.com/2025/05/androidify-building-delightful-ui-with-compose.html) 与 [2025-12 Android AI 示例目录](https://android-developers.googleblog.com/2025/12/explore-ai-on-android-with-our-sample.html)将品牌表达落实到组件、形状与动效体系。依据 Mote 的资料扫描 / 原文阅读任务，本轮采用清晰角色、稳定边界和适度强调，风格判断仍以三端实际呈现及用户反馈为准。这是本项目的设计取舍，不是对风格流行度的测量。

共同方向为清晰、安静、带可辨边界的资料工作台：冷中性色底、白内容面、单一蓝色强调、同一线性图标语法、系统无衬线字体、4 单位节距、规则化表面和按钮。阅读区保留正文 / 来源 / 时间的关系。Web 与 Mac 使用适合桌面的信息密度；Android 保留原生底栏、系统字体缩放、触控和键盘行为。

共享 `packages/shared/design-tokens.json` 从颜色扩展为排版、间距、表面 / 控件 / 阅读圆角和触控角色，由同一生成器输出 CSS 与 Kotlin。标题为桌面 24、手机 22，分组 16，行标题 / 正文 / 动作 14，辅助 13、元信息 12；数字是默认角色尺度，原文阅读和系统字体缩放保留适当适配。

## 固定八项指标

保留 [原七项](ui-focus-and-consistency-2026-10-13.md)。第八项“跨端统一美术风格”判断：同类标题、按钮、分组、表面、边界、分隔、图标和色彩在三端是否像同一产品，平台差异是否有角色依据。3 分为三套互不相干的风格；5 分为共享颜色但角色各自为政；7 分为多数共同角色已成立、仍有明显断裂；9 分为核心旅程和窄屏 / 大字体中风格连续且例外合理。0 为无法成立，10 为本轮检查范围未见缺口。

八项分别评价，无总分或新增权重。8.5 是新增项的努力目标，不是需要评估者凑齐的数字。用户审美反馈优先于模型分数；不会把独立模型“接受”写成用户已选择。

## 五轮序贯候选

| 轮次 | 演进主题 | 主要比较点 |
| --- | --- | --- |
| 1 | 共同视觉语法 | 去掉冲突的纸页 / pill 混用，接通角色 token；文字、图标、动作和表面遵守同一规则。 |
| 2 | 扫读与密度 | 减少重复页头和并列长说明，采用紧凑分组；重要状态、限制、范围与操作仍直接可见。 |
| 3 | 边界与分隔 | 同类按钮有一致的填充 / 描边，分组外壳与组内分隔清晰，菜单 / 表单 / 原文角色可分辨。 |
| 4 | 视觉重点 | 协调中性色、强调面积、导航及内容对比；避免大色块和大字争夺注意。 |
| 5 | 细节与节奏 | 根据前四轮反馈校准对齐、换行、触控和阅读，保留完整五个候选供用户比较。 |

每轮必须接收独立审图 / 实操反馈后进入下一轮。主题可依据反馈调整，不能仅改轮次名或复用前轮图片。最新源码是候选 5 的实现状态，不代表替用户选择第五轮。

## 第三轮边界角色

分组外框沿用轻边界 `#cad3df`；交互按钮 / 输入框描边使用 `#8090a5`，白表面与页面底色上的理论对比分别约 3.26 / 3.03；组内分隔使用浅色 `#e0e6ef`。这是共同角色的颜色约定，不等于完成无障碍认证；实际状态、焦点和窄屏由生成旅程另验。

## 第五轮细节取舍

Web 的辅助标签、空状态、图标与语言控件使用共同中性色；菜单按明确页面类型区分线性图标。随手记移除重复装饰标题，直接显示已有文件、不现场录音、附件先归档和单附件 50 MiB 的原有限制；OCR / 转写及逐阶段核对说明放在具名展开项中，全文仍可达。原文保持完整，长元数据自然换行，阅读行宽适当约束。

Mac 将来源类型和真实接收状态排列在同一标签列，完整文案使用自然宽度，正文与实际来源 / 时间在相邻阅读列。菜单保持既有导航与行为，修正复用图标和缺少图标造成的对齐差异。Android 按明确菜单项区分语言、插件、权限和诊断图标，日期 / 来源控件沿用共同 8 单位间距；英文计数使用“Records: 数量”，不改写采集到的原始来源名称。

这些改变不新增处理步骤、默认、权限或保留政策。第五轮的实际构建、四条件画面、原文 / 帮助 / 返回 / 键盘 / 生命周期验证与独立评分另见验证及评价记录。

## Supersession 与范围

KEEP：原功能 / 导航 / 来源 / 时间 / 原文 / 处理边界、设置职责、草稿、离线保存、权限和明确开始、保留 / 发送政策、已完成内容截图门槛。

CHANGE：三端共同视觉体系、排版密度、分组 / 边界 / 分隔、辅助说明的层级、角色 token、每轮完整来源记录和候选比较。

REMOVE：Mac 纸页书脊和 serif 与其他页的混搭、无角色依据的圆角 / 字号 / 色板、重复页头、无可辨识边界的同类操作、旧美学分数自动继承。

EXCEPTION：原生导航与系统控件不要求像素完全相同；高风险确认、实际错误 / 限制、采集范围和执行状态保持可见。辅助教学可按明确标题展开，全文可达；不按内容关键词决定布局或用户意图。

UNKNOWN：实机、真实采集 / 模型 / 账号、真人理解和完整无障碍研究单独报告。

## 记录与验证

基线固定为 `b52d6275` 与已冻结的反馈后实际截图。五轮分别保存源码提交、token、构建身份、实际 APK / 测试 APK、原始 PNG、内容就绪 JSON、实际旅程、独立八项评价与下一轮取舍。不能将失败的截图包装成完成页。

同一轮只有一个平台需要修复时，其他端可保留该轮已完成的真实构建，明确记录原 producer SHA 与新聚合候选 SHA。必须由实际 `git diff` 证明本端源码及全部共同构建输入逐字未改，并保留原 manifest / PNG 来源；不能将旧 producer SHA 改写为新构建，不能以此借用其他轮的图片。任一本端或共同输入变化均需重建该端。

共同核心矩阵覆盖首页、内容、随手记、原文、问一问、设置、连接和导入，中英文 × 常规 / 窄屏；Android 窄屏含 130% 字体。每轮实际保存并核对原文、设置职责与原任务返回；重点变化补测相应状态。首末轮详细验证草稿 / 生命周期 / 键盘及限制，其他轮不能仅审缩略图。

所有测试后台执行，只用生成资料。Android 保留 `FLAG_SECURE`，只绘制应用自己的真实窗口，实际 IME 下布局与系统键盘像素分开说明。最后使用 `npm run check:affected` 验证最终受影响组件及消费者。离线候选页提供轮次、平台、语言、条件与场景选择、两轮对照、原图放大、每轮评价与本地倾向记录；不发布应用。
