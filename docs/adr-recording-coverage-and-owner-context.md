# ADR：录音覆盖编号与日记本人对应

日期：2026-10-12。状态：采纳，所有者已确认修复方案。

## 问题与决定

少量真实录音验证出现两个问题：模型反复返回不完整的 64 位覆盖标识，修正过程中又发生供应商失败；具名第一人称日记虽收到所有者的来源说明，仍全部作为未确认主体的观察。原件导入及引用坐标是完整的，不能用重导入、模糊匹配或全库重跑解决这两个问题。

Agent 的 `memory-context@3` 投影用批内 `member_N` 编号表示宿主已冻结的目标、语境、授权目录和检查历史中的成员。独立审核草稿使用同一投影。Codex 与兼容模型适配器只把本次已提供的精确编号还原成原有规范标识，再进入覆盖、候选、引文和授权校验；未知编号及损坏的规范标识保持无效，不猜测、不按返回行位置补齐。语境成员或未读授权目录成员即使有编号，也不能冒充本批目标。正文、引文、证据 UUID、范围、声明和持久化标识不变。

新增 `mote.recording-memory@2`，提取与独立审核都解释宿主提供的 `sourceContextStatements`。所有者说明与实际正文可以建立其明确描述的日记叙述者对应；`unknown/default` 只表示没有设置类别默认，不是否定所有者说明。账号、昵称、第一人称和说话人标签本身仍不足以证明本人。主要是日记的说明不把多人对话、转述或背景导航全部归给主人；当前明确的来源或单份纠正优先。模型判断实际适用范围，确定性代码不猜姓名、不识别语义关键词、不把来源强制改为 owner。

原录音 v1 的提取、审核、配方和指纹保留，新建录音来源使用 v2。已有来源覆盖及旧任务不静默换版本；本次用户明确授权的目标来源通过正式设置接口选择 v2，现有五份资料通过正式历史任务重新验证。普通默认、其他来源、模型、并发和周期同步范围不变。修复不要求新导入说明或逐份身份确认，不新增自动历史收费工作。

## 取代检查

| 类别 | 处理 |
| --- | --- |
| KEEP | 精确原件、完整目标覆盖、逐批独立审核、授权和撤权、版本化归属、未知主体的有限观察、模型解释语义。 |
| CHANGE | 模型传输的覆盖标识用短编号；录音 v2 明确结合来源说明与正文建立叙述者对应；通用宿主声明指令区分未设默认和否定对应。 |
| REMOVE | 要求模型抄写长哈希才能证明完整覆盖；将 unknown/default 当作所有者范围说明的否决条件。 |
| EXCEPTION | 旧规范覆盖标识仍可严格验证；已有 v1 配方和任务保留；没有足够对应关系的多人发言仍保留不确定性。 |
| UNKNOWN | 所有者说明不做声纹或现实身份验证；模型仍可能误解混合发言；供应商修正失败不等于已确定网络根因。 |

影响面包括 Agent 请求投影、两种模型适配器、独立审核草稿、录音配方及来源初始选择。MemoryStore、覆盖 schema、检查点、隐私和授权没有放宽。该决定细化[上下文与引用 ADR](adr-memory-context-and-canonical-evidence.md)、[资料归属 ADR](adr-material-attribution.md)与[有限个人 Memory ADR](adr-bounded-personal-memory.md)。

## 验证

生成回归通过实际 Codex 适配器运行 20 个成员的提取、非法编号拒绝与原会话修正、独立复核和规范检查点。另检查审核草稿、授权目录与检查历史的精确编号往返；正文与引文不得被替换，未知编号不得被猜测。正式录音入口的 fixture 覆盖来源说明、unknown 默认、v2 选择、独立复核、重启以及 v1 固定定义。

真实模型另用所有者已选择的五份原件复验：长录音全部范围及原失败片段、具名日记本人经历、匿名单人日记、混合电话他人症状与背景导航、计划与完成、原始时间与采集时间，以及保存引文的 UTF-16 坐标。Fixture 只证明传输、生命周期和校验，不证明模型语义质量；每轮真实结果保存在私有目录，不进入版本库。此检查使用厂商既有转写，不声称新 ASR、声纹或物理设备验证。
