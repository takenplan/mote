# 文件归档与中央处理

中央文件处理使用 Cordis，支持本地多人录音、说话人分离、导出和人工复核。部署与扩展说明见 [中央文件处理](file-processing.md)。

实现与扩展设计见 [文件同步设计](file-sync-design.md)，实测记录见 [文件同步验证](file-sync-validation.md)。

## 当前行为

- Android 使用系统文件选择器授权目录。录音原样上传，成功确认后仅清理 Mote 格式 4 原始字节暂存，保留手机原文件。
- 来源删除只记录“原位置已不可见”。中央保留已归档的原件、历史版本、转写和摘要。它不能证明原文件确实被人删除，也可能是移动或提供方变化。
- **原件归档**保存精确字节；**引用 / Shadow**只保存名称、路径、大小、时间等元信息，不打开正文，不计算原件散列，不生成内容摘要。
- 现有文本快照、日历和 MCP 导入各自遵守当前账号协议。统一的来源与版本模型支持后续 NAS 常驻扫描器；当前尚未提供 NAS 二进制同步客户端。
- 原件独立于处理任务。未配置转写服务、格式不支持、模型失败时，归档成功仍然有效。

## 手机设置

在 Android 首页打开「同步文件夹」，选择「音频文件」预设，点击「选择文件夹」后用系统选择器授权录音目录；填写选填资料说明并确认中央保存方式，点击「开始同步」。音频预设只是扩展名与新任务保存方式的组合，复用通用文件同步及中央转写处理链；「仅记录文件信息」不会读取或转写正文。已有来源继续保留原设置。

「导入文件」使用同一套编辑页，默认只导入选定文件一次。资料说明是可修改的来源元信息，作用于已有及未来资料，不直接创建全局 Memory，不自动重算历史收费任务，详见[文件任务决策](adr-file-source-context.md)。中央 Web 导入批次的说明仍限定于该批新增原件。

每个来源可以设置扩展名、排除路径、扫描间隔、保存方式及首次同步范围：

| 配置 | 行为 |
| --- | --- |
| `all`，默认 | 分批导入所选范围的已有文件，然后同步新增及变化版本 |
| `new_only` | 第一次完整扫描只建立基线；只上传之后首次出现的文件，已接入的新文件仍跟踪变化 |
| 从 `new_only` 改为 `all` | 补归档基线中的旧文件；已经确认的版本不重复归档 |

“只同步新增”不是简单按文件修改日期截断。跨扫描页、重启仍保留基线。初次扫描期间新出现的文件可能进入基线；基线文件的后续修改也不会自动接入，需改为 `all`。

文件上传遵守 Mote 现有手动、实时、定时或批量同步策略，以及 Wi-Fi、充电和电量条件。每个文件需要连续 60 秒元数据稳定；暂存前后再次核对大小、修改时间和文件身份。Android 提供方若在字节变化时仍报告完全相同的元数据，无法据此保证录音已经结束。

### Android 同步进度

首页的文件夹、来源管理和文件详情显示同一份整体进度：中央已接收的当前版本数 / 已清点且在发送范围内的版本数，以及等待稳定、排队、正在保存、正在上传、失败重试和需处理的数量。扫描未完整时明确标注总数仍会增长。首次 `new_only` 的基线文件单独显示，不计入待发送总数；文件发生变化后，旧版本回执不计入新版本的已接收数量。

- **等待稳定**：尚未保存字节，距最近观察到元数据变化不足 60 秒；显示剩余等待时间。引用模式、删除事件和单文件一次性导入沿用各自现有例外。
- **排队**：已经具备保存条件，或已有暂存字节等待上传/续传；尚无正在执行的传输。
- **正在保存 / 正在上传**：来自当前进程实际执行的文件准备和传输操作；持久化暂存和系统重启不会被误显示为正在上传。
- **失败重试**：保存或传输失败，保留文件级诊断及已知 HTTP 状态码；在下一次实际尝试或确认成功后更新。协议冲突、中央遗忘或协议升级要求显示需处理，不声称自动重试能解决。

整体进度同时说明暂停、连接、Wi-Fi、充电、电量以及手动/定时/批量策略的等待条件，不改变这些条件。接收成功与中央整理、建立索引分开显示。

文件详情只在前台每 2.5 秒检查本机状态，更新状态和文件夹进度，不重建正在阅读的内容；当前版本或接收回执变化时重新加载详情，中央处理或索引仍在运行时每 5 秒检查中央状态。每次只保留一个读取任务，后台暂停、恢复和 Activity 重建会重新核对当前状态；自动内容更新保留原文页码和滚动位置。手动刷新仍可使用。

对应回归和本轮验证边界见 [Android 文件同步状态验证](validation/android-file-sync-status-2026-10-13.md)。

### 首期容量边界

| 项目 | 边界 |
| --- | --- |
| 原件 | 每文件 512 MiB；超过上限可用 Shadow |
| 传输块 | 4 MiB；每次后台派发最多上传 2 块 |
| 手机文件暂存 | 合计 1 GiB；每来源同时暂存一个原件 |
| 扫描 | 每片 200 个条目，保存目录游标后续跑 |
| 清单 | 每来源 50,000 文件、深度 32、待遍历目录 10,000 |
| 来源数 | 不按累计来源数拒绝新增；单来源扫描与暂存边界仍适用 |
| 文字提取 | UTF-8 `text/*`，每文件 2 MiB；另有内置 PDF/DOCX/XLSX 文档解码，受各格式上限限制 |

待同步标记与当前上传项单独持久保存，计数和逐文件确认不会反复解密整个目录。权限或提供方异常不作为来源删除；源目录操作与中央遗忘是不同操作。手机强制停止应用后，后台恢复仍受 Android 系统规则约束。

## 中央处理设置

在中央网页「设置 → 文件与语音」管理当前账号的运行设置及类型策略：

- 可关闭自动处理、调整音频最长时长（默认 120 分钟，1–1440 分钟）、单次调用预算、匿名说话人和摘要/语义选项；没有每日音频时长限额。
- `filePolicy.policy.services / profiles / rules` 分别选择服务引用、处理方案和 MIME 规则。可选择个人自定义 HTTP 转写连接，也可选择管理员提供的共享连接；个人连接的端点、密钥保存在本账号 `models.profiles`，处理策略只保留 `{kind:personal|shared,id}` 引用，不复制密钥。远端需明确启用且使用 HTTPS，更换目标不能静默继承旧密钥。
- 管理员管理共享 media 安装和共享连接，普通账号不能读取共享密钥；这不取消个人自定义服务。默认本地多人录音、仅归档、转写接口及来源覆盖的用户旅程保留，准确方案字段见[类型策略](file-processing-policies.md)。

运行设置保存在当前账号 YAML 的 `processing` 域，版本化策略保存在 `filePolicy.policy`，与个人 models 变更共同经过 revision 校验。配置变化不会自动重做全部历史收费任务；新任务使用固定策略与连接指纹，旧结果不能写回新配置任务。资源忙时持久等待，不消耗失败预算；已成功的转写和摘要检查点保留，重启或单步重试不要求重新上传原件。详见[配置所有权](configuration-ownership.md)和[中央文件处理](file-processing.md)。

### 可选本机 Whisper 服务

安装固定版本依赖、FFmpeg 并预先准备模型。最新启动命令、多人说话人分离、本地模型配置及持续运行的服务模板见 [中央文件处理](file-processing.md#在中央主机启动本地服务)。

仅英文 tiny.en 合成录音属于链路验收；中文、嘈杂环境、长录音仍需对应模型与样本验证。

### 自定义转写实现

中央向配置的 URL 发送 `POST`，正文为原始音频字节：

```text
Content-Type: application/octet-stream
Content-Length: <原件字节数>
X-Mote-Max-Audio-Ms: <本次剩余时长预算>
Authorization: Bearer <可选密钥>
```

返回严格 JSON：

```json
{
  "durationMs": 12774,
  "segments": [
    {"startMs": 2240, "endMs": 6000, "text": "示例转写", "speaker": "可选说话人"}
  ]
}
```

时间必须有效并有序，空 `segments` 表示识别未得到语音。最多 50,000 段，每段最多 8,000 字符，响应最多 32 MiB。服务应先测量音频实际时长并遵守预算；中央还会验证返回时长。当前扩展通过[插件作者指南](plugin-authoring.md)中的宿主 processor 路径。旧单所有者宿主曾支持在自定义启动程序注入 `TranscriptionProvider`；这不是当前 `buildScopedApp` 的安装入口。

## 分层、检索与使用

1. **原件 / 引用**：来源、不可变 revision、相对路径、散列及可用性。
2. **转写 / 提取**：独立 artifact 与 chunk UUID，音频片段带时间范围，保留原件不变。
3. **索引**：FTS 全文检索；配置现有 embedding 服务后，片段也进入向量索引。
4. **摘要**：以已读取的片段 ID 为依据的模型产物。
5. **记忆**：按原件授权、当前配方、独立模型审核与 fenced 保存发布；需要用户回答的事项另走澄清流程，模型产物不当作独立原始事实。

Agent 和只读 MCP 经当前资料/文件读取工具按需、逐页展开转写。模型必须先发现文件，引用必须来自本轮已读取、仍有效且在选定设备与时间范围内的片段。工具不会自动打开来源 URI 或临时拉取 Shadow 正文。

网页可按来源、文件名/相对目录及音频/文本类型查找。摘要引用可以打开对应片段；音频通过短期、限定到单个文件的 HttpOnly 凭证回听，支持 Range 请求和定位时间。浏览器不支持某编码时下载原件；自动生成播放转码副本尚未实现。

重新提取产生新的产物版本，旧索引不再参与当前检索。中央显式遗忘会删除该文件的全部归档版本与派生层，并阻止离线重试恢复；共享字节在其他文件仍引用时保留。旧问答、记忆和洞察使用现有保守的失效策略。物理无引用对象经回收宽限期移除。

## 协议与存储扩展

当前 Wire 2 / Ingress 3 使用账号与来源限定的路由，握手、文件 revision 和接收凭据详见[协议](protocol.md)。来源 `/head?externalId=…` 可查询版本锚点；已暂存 revision 不自动改写。

原件通过 `POST /api/ingress/sources/:id/uploads` 提交 `{batchId, revision}`，按已确认块续传 `PUT /api/ingress/uploads/:id/parts/:part`，最后 `POST /api/ingress/uploads/:id/commit`。块以 JSON base64 及校验和传输，服务重算整文件 SHA-256。接收凭据绑定部署、账号、来源、批次和成员；丢响应沿用相同身份重试，不转用旧 `/api/file-sync/v1`。

Shadow 和来源消失通过 `/api/ingress/sources/:id/items` 提交当前版本；前驱 revision 防止乱序覆盖。来源授权、排除规则、去重、传输和保留使用确定性代码；正文含义交由模型判断。

私有文件对象位于 `originals/<部署与账号散列>/objects/<sha256>/<part>.plain|.aes`。个人 `storage.contentEncryptionEnabled` 默认关闭；启用后使用账号托管密钥逐块 AES-GCM 加密，没有个人可配置的全局 `storage.dataKey`。SQLite 仍保存规范内容与派生索引；部署者可接触服务器明文和托管密钥，因此仍需保护整个数据目录，见[内容存储](content-storage.md)。未完成上传会话过期后，客户端保留暂存并重新建会话。

## 备份与恢复

当前完整备份使用停止状态的实例目录及显式配置文件，不是旧文件 JSON 导出：

```sh
npm run backup -- --data /absolute/data --config /absolute/instance.yaml --out /absolute/new-backup-directory
```

完整备份含 SQLite、原件、配置和托管密钥等恢复所需私有数据，按秘密材料保护；不能把它视为不含凭据的分享包。恢复到新空目录会撤销旧授权，不重放旧未知外部操作。可信密码登录按当前配置恢复本人未来策略，设备另需重新配对。个人便携归档 version 3 与完整实例备份不同，不含账号凭据、任务、私人配置或托管密钥，且只导回原部署/账号。命令、校验和恢复边界见[部署与备份](deployment.md)及[生命周期决定](adr-lifecycle-parity.md)。

## 当前 Android 格式与验证

Android 本机文件队列和 transport checkpoint 使用格式 4；缺少版本或版本不符明确拒绝，不重建旧 checkpoint。Prod / Test 的凭据与中央私有草稿/操作 ledger 使用 Keystore SecretBox；Dev token 使用私有 JSON，SecretBox 使用私有 JSON AES 密钥，私有正文仍认证加密；本机文件暂存不再使用可选内容加密。更改本机保存位置和断点重试仍处理当前格式数据。中央文件对象的存储策略由上文及中央内容存储规范定义。

2026-10-04 历史清理验证：54 个 JVM 测试类、245 项测试全部通过（0 失败、0 错误、0 跳过）；instrumentation Kotlin 源码编译与 debug APK 构建通过。未运行模拟器或物理设备 instrumentation、真实模型或个人数据检查。该记录未在本次文档修订中重新执行。

使用独立包 `dev.mote.collector.filefixture`，避免更新日常开发包。详细命令和已执行边界见 [验证记录](file-sync-validation.md)。
