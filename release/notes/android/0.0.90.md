# Mote Android 0.0.90

- 采集范围、排除与遮罩、OCR、采样与画质、网络同步、上传副本保留及预览确认按账号保存；A→B→A 恢复各自偏好，同账号换凭据或已核验节点地址保留偏好。首次无账号快照使用原默认值并停止采集，继续通过原显式开始／预览流程启用。
- 混合上传遇到明确冲突或删除时隔离对应记录，批次过大时拆分重试；每条已核验 ACK 立即结清，后续网络失败保留此前成功进度。单条仍超限时保留未确认状态。
- 区分来源暂停、永久拒绝和暂时失败，暂停时保留待发数据；上传会话过期可重试。无法确认来源是否暂停时保留可重试状态，避免误写为永久冲突。
- “同步与恢复”的检查、补传、停止与迟到结果受当前账号约束，切换账号退休旧控件；已显式连接的日历工作在设置应用、重新登录和启动后恢复，其他账号不会继承连接。
- 原生中央模型页恢复个人配置编辑、复制／删除、保存前目录与连接测试及各功能独立模型选择；更换服务目标后复用凭据需明确确认。文字识别、历史处理和 OCR／ASR／说话人模型状态及管理员安装／取消入口使用当前账号合同。
- 文件页展示仅登记目录、无原件或无当前处理正文的条目，只提供实际可用的保存、导出、纠正和重处理操作；录音页分别显示文字与音频阶段、尝试、错误和下次运行时间。
- 登录、邀请、协议、权限及网络／代理错误显示对应恢复提示，避免将传输故障误报为账号问题。
- 关闭打包上传时，在载荷构造前只读取本次发送的一条记录，减少长队列重复读取和临时载荷；打包模式、顺序、重试及 ACK 规则保持。
- 稳定标签改用 Prod 包和常规诊断，Prod 保留 Android Keystore；独立 Dev Profile 使用应用私有文件凭据与密钥，不改变第三方 CLI 凭据管理。

versionCode 递增至 **101**。本次稳定标签为 `android-v0.0.90`，附件为 `mote-android-arm64-0.0.90.apk`，Prod 包名 `dev.mote.collector`。上次 `android-v0.0.89` 的资产使用旧 Dev 包名 `dev.mote.collector.dev`；新 Prod 与它分别安装，不会覆盖或自动导入旧 Dev 的设置、凭据及队列。已有同包、同签名且当前格式的 Prod 安装可覆盖更新，不能以 code 101 推断不同包之间能够覆盖。Dev 后续从 Actions 获取按提交标识的 Artifact。详见[更新说明](../../../docs/updating.md)及[Profile 决定](../../../docs/adr-profile-release-policy.md)。

沿用 Wire 2、Ingress 3 和本机格式 4，与当前 Central 契约配套；没有新增旧格式兼容或自动迁移。旧加密 Dev 状态不会自动转成文件凭据，须先保留旧程序与资料，再按更新说明显式重建 Dev 存储；此步骤不用于正常 Prod 更新。发布 APK 不会安装到设备、更新日常 profile 或部署中央；当前产物仍手动安装。

保留 `FLAG_SECURE`。已有生成素材／模拟器子范围见[Android 记录](../../../docs/validation/parity-android-20261018.md)及[性能记录](../../../docs/design/performance-round1-F-review-and-validation.md)。最终组合的检查范围、原始失败、后继结果与未覆盖事项见[集成 PR #201](https://github.com/utopiafar/mote/pull/201)；历史分候选结果不能改写为最终组合的新执行或原生权限全覆盖。发布构建及实际 APK 的包名、版本码、固定签名、非 debuggable 和 16 KiB 对齐校验以 `android-v0.0.90` 对应的实际 Release CI 运行报告为准，报告链接在同一 PR 中汇总。实体手机、OEM 后台恢复、Prod 权限交互、真实模型、个人屏幕采集、安装和部署未由这些生成素材回归验证。
