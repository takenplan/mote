# Mote Central 0.0.91

- 恢复账号作用域中的资料、Memory、问一问、连接器、配置、行动和生命周期流程，同时保留账号、来源、原件修订及撤权边界。
- 文件目录支持仅登记元数据、原位置已移除但中央仍保留原件的条目，以及相对路径查找；处理结果保留原设备与资料时间。管理员可通过预览、确认流程导入中央主机目录。
- 将原件保留与处理方案分开，恢复图片 OCR、图像理解、命名产物及父附件组合；没有配置 OCR 的理解方案仍可使用原图。过期上传可以重试；已提交且规范原件仍在时可恢复 ACK，无需重传原始分片。
- Memory 恢复连续批次内的提取、纠正、独立审核和保存，同一原件的个人与 Coding 域分别推进；保留成功检查点、完整证据和严格的 Coding 候选复用。独立整合窗口不会被前一窗口的失败或暂停阻塞。
- Memory 评估时间由首次准入、原件接收或整合窗口选入时固定；重试、重启、反馈、Owner 续评及独审沿用对应快照，来源事件时间保持原义。固定提取和整合使用现有中性程序，审核后的关系仍按既定合同原子应用。
- 问一问恢复按账号的可选向量与混合召回、来源说明发现、目录预览、失败轮次历史和外部结果分页；读取和发布继续核对当前原件与已披露证据，已撤权或删除的旧响应不能重新发布。没有自动收费的历史索引回填。
- 配置页恢复个人草稿试连、保存前模型目录、各功能独立模型选择和专用资源控件；更换服务目标后复用凭据需要明确确认。用量页恢复日期、时区、筛选、分组、明细和个人价格，并记录调用片段与业务归因；未知费用保持未知。
- 连接器在单次同步失败后保留后续轮询，遵守自动同步开关和显式预览确认。录音使用单份规范转录正文及原始定位，文字、音频备份和 Memory 阶段独立显示失败与重试；已确认音频可在同一授权来源内复用，备份不会自动启动 ASR。
- 恢复交互与后台任务的并发设置、公平等待、业务父子进度和持久尝试计量；行动发现、批准及原生执行状态各自保留正确来源，重启不会盲目重发结果未知的外部写入。
- 插件检查先验证实际能力再启用，组合组件按身份匹配并传递取消；MCP 保留一次导入、无状态调用和可选发现方法的合同，私人访问仍要求账号与来源授权。
- 恢复已配置的保留期限、实例共享逻辑容量和启动／定时清理；容量拒绝不会误发保存 ACK。个人完整导出与实例备份继续分开；实例恢复后以密码重新登录建立新权，按原开关继续未来策略，不恢复旧任务授权。
- 网页恢复首页及可见设备刷新、同页证据交接和准确的登录／权限／网络恢复提示；提问输入减少对历史对话的重复渲染，附件分片复用已计算的校验和。当前原件、Operations、执行 tick、连接器和插件的读取减少重复数据库工作，每次当前授权检查仍保留。
- 文档新增项目地图与逐项进展台账，区分实现、原验证、未闭合旅程、发布和部署；不再把旧审计中的“无保留执行”“无向量召回”等描述直接当作当前源码状态。

本次稳定标签为 `central-v0.0.91`，附件为 `mote-server-0.0.91.tar.gz`，包含同版本 server/web 及构建依赖源码，不包含运行配置、凭据、模型权重或个人资料。上次 `central-v0.0.90` 是旧 Dev prerelease；当前采用 Profile 优先的发布规则，运行 Profile 仍由私有 YAML 选择。发布源码包不会部署、切换或重启任何中央节点，也不恢复 GHCR 镜像或签名在线更新。安装步骤见[更新说明](../../../docs/updating.md)及[发布规则](../../../docs/releasing.md)。

沿用 Wire 2、Ingress 3、中央 storage epoch 5、客户端本机格式 4 和个人便携归档 version 3；本次没有新增旧格式兼容或自动迁移入口。同代部署保留当前 profile 与正常持久状态，跨代边界及备份步骤仍按更新说明执行。

已知边界继续保留：ZIP／Markdown 相对附件关系、既有已删文件的历史目录补全、原图片 Memory 实际保存失败及一般插件完整案例等，不能由源码合入或本次功能门禁一并宣告关闭。MEM-Q1 的自动入队等待候选不属于本次 Memory 时间修复。具名状态及原证据见[项目进展台账](../../../docs/project-progress.md)。

验证范围：已有回归使用生成素材、隔离账号、临时资料库及模拟供应方，分候选证据见[进展台账](../../../docs/project-progress.md)、[性能记录](../../../docs/validation/performance-round1-integration-2026-10-20.md)和[Memory 时间修复记录](../../../docs/validation/memory-evaluation-context-restoration-2026-10-20.md)。最终组合的检查范围、原始失败、后继结果与未覆盖事项见[集成 PR #201](https://github.com/utopiafar/mote/pull/201)；分候选通过不能代替最终组合验收，也不表示既有 Server 负载失败的根因已解决。发布构建与源码包校验以 `central-v0.0.91` 对应的实际 Release CI 运行报告为准，报告链接在同一 PR 中汇总。真实模型／embedding 质量、实体设备、Prod 权限提示、个人内容采集和部署未由这些生成素材回归验证。
